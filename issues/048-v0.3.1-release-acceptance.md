# 048: v0.3.1のリリース受入

## 状態

自動受入を実施中。Issue 045、046、047の実装を完了し、実環境と外部clientの受入を残す。

## 目的

v0.3.0の公開仕様とデータを維持したまま、復元可能性、運用診断、browser・MCP回帰試験を
追加した`v0.3.1`を受入・公開する。

## 公開範囲

- archive検証、空databaseへの復元試験、backup timerと安全な世代管理
- Kanidm 1.10、browser、subpath、OAuth、MCP protocolの自動回帰試験
- systemdとjournaldを中心とする運用診断

MCP入力診断、検索拡張、Web編集、グラフUI、PostgreSQLは本releaseに含めない。

## 自動判定

1. `cargo make release-gate`が成功する。
2. NixOS VMでbackup、隔離した空databaseへの復元、論理内容の一致を確認する。
3. Kanidm 1.10、private CA、subpath、browser login、MCP OAuthのE2Eが成功する。
4. backup破損、空でないimport先、OIDC到達不能、認可取消、protocol不正の失敗経路が安全側で終了する。
5. OpenAPI、MCP、NixOS option、運用文書の整合性検査が成功する。

## 実環境受入

1. NixOS moduleを更新し、既存のv0.3.0 databaseを保持したまま起動できる。
2. 日次backupと30世代保持の設定、最新成功世代、purge timerを確認する。
3. 最新archiveを本番から隔離した空databaseへ復元し、代表ノート、ACL、削除状態を確認する。
4. `server-users`、`server-admins`でOIDC loginと可視性を確認する。
5. ChatGPT、Claude Code、Codex CLIでMCP login、read、write、revokeを確認し、client版を記録する。
6. 失敗を模擬し、systemd status、journald、request IDから原因を追跡できることを確認する。

## 公開条件

- Issue 045、046、047の完了条件を満たしている。
- 公開API、archive format、SQLite schemaに意図しない破壊的変更がない。
- Pull Requestが`main`へマージされ、対象commitでrelease gateが成功している。
- 上記commitへ`v0.3.1`tagを作成し、tag起点のrelease gateが成功している。

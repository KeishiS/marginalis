# 037: v0.3.0のアーキテクチャ再設計

## 状態

実装中。確定設計は [v0.3.0 再設計仕様](../docs/v0.3.0-design.md)へ記録した。`v0.2.0`で公開した
API、データ形式、ローカル `root` 認証との後方互換性を維持しない。本 Issue は後続 Issue の
設計決定と完了境界を管理する。

## 目的

機能追加より先に、正本の二重永続化、アプリケーション内の利用者管理、将来の Web UI に
備えた過剰なクレート分割を解消する。10 人・約 1,000 ノートの単一インスタンス運用で、
開発・障害復旧・認証運用のコストを下げる。

## 決定事項

- SQLite を唯一の正本とする。ノート本文、メタデータ、ACL、削除状態、検索・参照投影は
  同じ SQLite トランザクションで更新する。稼働中の `dataDir` と操作ジャーナルは持たない。
- AsciiDoc は入力、表示、export/import の形式とする。ノート単位の `.adoc` export と、
  全ノート、ACL、削除状態を含む検証可能な archive を提供する。
- `v0.2.x` の保存データ、`/api/v1`、データフォーマット v1 は移行しない。新版は空の
  SQLite から初期化する。旧版からの一回限りの export/import を提供するかどうかは
  新版の実装範囲に含めない。
- 利用者の有効性と全体管理者権限は Kanidm 1.10 のグループへ完全委譲する。通常利用者は
  `server-users`、管理者は `server-admins` とし、管理者には全ノートの閲覧・管理を許可する。
  ローカル `root`、登録ポリシー、招待、SMTP は廃止する。
- 所属グループは OIDC login 時に署名検証済み `groups` claim から確定する。変更は次回 login から反映し、
  既存 session と MCP token は有効期限または認可取消まで発行時の権限を保持する。
- MCP の OAuth Authorization Server は Marginalis に残す。Kanidm は本人認証と所属判定だけを
  担う。Authorization Code + PKCE、OAuth discovery、Dynamic Client Registration / Client
  Metadata を維持し、ChatGPT、Claude Code、Codex CLI との接続を対象にする。
- 削除は 30 日間のソフトデリートとする。通常の API、MCP、Web UI、検索、グラフから即時に
  除外し、毎日自動で物理削除する。本文履歴は保存しない。
- 新 API は `/api/v2` とし、OpenAPI を新設する。旧 API を同一バイナリで提供しない。
- Rust の内部境界は、`core`、`asciidoc`、`sqlite`、`http`、実行バイナリの最小単位へ再編する。
  PostgreSQL 向けの抽象化は実需要が生じるまで追加しない。

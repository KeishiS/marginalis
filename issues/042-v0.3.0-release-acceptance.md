# 042: v0.3.0のリリース受入

## 状態

受入中。2026-07-25 に設計監査とセキュリティ再監査後の `cargo make release-gate` が成功し、
Rust、OpenAPI、RustSec依存監査、release package、強化したNixOS service sandbox、
実バイナリによるbackup・30日purge、Kanidm 1.10.4 TLS Discovery E2E を確認した。
OIDC ID tokenはKanidm 1.10の`ES256`を受理し、RSA署名方式を拒否する。
残作業は実配備した環境での
OIDC browser login と ChatGPT、Claude Code、Codex CLI の手動 MCP 受入である。

2026-07-25の公開環境に対する読み取り専用の事前確認では、`GET /api/v2/health`は`200`だったが、
authorization server metadataとprotected resource metadataは`404`だった。最終候補の配備と
`services.marginalis.mcp.enable = true`の反映後に手動受入を開始する。

## 目的

SQLite 正本、Kanidm group 認可、新 API、MCP OAuth、閲覧用 Web UI、ソフトデリートを含む
`v0.3.0` を、空の新環境で公開可能と判断する。

## 受入範囲

1. 空の SQLite を初期化し、`server-users` と `server-admins` による OIDC login と認可を確認する。
2. REST `/api/v2`、閲覧用 Web UI、MCP が同じ ACL と管理者可視性を適用することを確認する。
3. ChatGPT、Claude Code、Codex CLI の MCP OAuth login、read/write、認可取消を確認する。
4. ソフトデリート、復元、30 日経過後の自動 purge を確認する。
5. NixOS module、Kanidm 1.10 E2E、TLS、subpath、release gate を確認する。

## 公開時の方針

- `v0.2.x` の database、`dataDir`、API、MCP token は利用しない。運用者は新しい空環境として
  初期化する。
- `v0.2.x` の保存データを必要とする運用者は、旧環境を読み取り専用の退避物として保管する。
- archive 復元の自動受入は本リリースの必須条件に含めない。

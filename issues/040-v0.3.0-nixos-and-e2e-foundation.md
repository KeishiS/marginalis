# 040: v0.3.0のNixOS配備とKanidm 1.10 E2E

## 状態

実装中。NixOS module は v3 SQLite 正本、v3 archive backup、日次 soft-delete purge へ更新した。
固定 nixpkgs に `kanidm_1_10` 1.10.4 が含まれることを確認した。module の probe VM は service、
backup、purge timer を、runtime VM は SQLite 初期化、health、OpenAPI、OIDC 未到達時の fail-closed を
実行している。Kanidm を含む TLS/subpath/OIDC/MCP E2E は残作業である。

## 目的

実運用と同じ Kanidm 1.10、NixOS モジュール、TLS 終端、サブパス、remote MCP client を通す
再現可能な受入基盤を作る。

## 作業内容

1. nixpkgs と NixOS VM の Kanidm を本番と同じ 1.10 系列へ固定する。
2. NixOS module を SQLite 正本、archive export/import、日次ソフトデリート purge、Kanidm group
   設定、MCP OAuth の新しい運用契約へ更新する。
3. server VM（Marginalis、nginx、Kanidm）と client VM で、TLS、subpath、OIDC login、グループ
   変更、REST、MCP OAuth、閲覧用 Web UI を検証する。
4. E2E は失敗時に非秘密の server log、request ID、browser trace を取得する。Cookie、token、
   authorization code、client secret は成果物へ含めない。
5. Kanidm 1.10 E2E、MCP 認可、NixOS 配備を `v0.3.0` の必須 release gate に追加する。

## 対象外

- archive からの復元を release 条件とすること。復元試験は後続の運用改善として扱う。
- 本番 Kanidm・本番 proxy への自動操作。

## 完了条件

- `nix flake check`から Kanidm 1.10 を使う E2E を再現できる。
- NixOS module による配備、OIDC group 認可、MCP OAuth、TLS と subpath が成功する。
- 失敗時 artifact の秘密情報除去と保持方針が文書化されている。

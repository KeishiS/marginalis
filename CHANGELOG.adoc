= 変更履歴

[#top]
この文書には利用者に影響する変更だけを記録する。
公開 API、データフォーマット、NixOSモジュールの動作を変えない内部的な再構成は記載しない。

[[0350--2026-08-07]]
== 0.35.0 — 2026-08-07

*改善*

* ノート閲覧画面で、見出しと本文の大きさの差が極端だったため本文が読みにくかった。文書題名と
``==``の章見出しが同じ大きさで表示され、本文との比が2.7倍になっていた。題名から本文まで段階的に
変わる大きさへ改め、本文も少し大きくする。あわせて、1行が長くなりすぎないよう文章の幅を制限する。
表、コードブロック、数式は従来どおり広い横幅を使う。
* 定義リストに書式がなく、用語と説明を見分けられなかった。用語を太字で示し、説明を用語より内側から
始めて縦線で範囲を示す。
* 狭い画面で、書誌、関係の図、設定への移動手段が隠れていた。URLを直接入力する以外に移動できな
かったため、ヘッダーへ「メニュー」ボタンを追加する。広い画面では従来どおり横に並べる。いま開いて
いる画面も示す。

*修正*

* MCPクライアントへ許可するscopeの上限を設定していた場合に、同意画面が上限を超える権限まで
選択できるように見せていた。許可しても上限を超える分は付与されず、エラーも表示されないため、
クライアント側でもMCPアクセス設定でも変化が分からなかった。上限を超える権限は選択できないように
し、要求されたが許可できない権限として理由とともに表示する。要求された権限がすべて上限を超える
場合は、同意画面を出さずにクライアントへ``invalid_scope``を返す。
* クライアント別のscope上限を、一度設定すると解除も拡大もできなかった。上限は今後の認可を制限する
設定であり、それ自体は権限を与えないにもかかわらず、これまで同意した権限の範囲内でしか変更でき
なかったため、狭めた上限から復旧できなかった。MCPアクセス設定へ「上限を解除」を追加し、上限は
サーバーが対応する全scopeから選べるようにする。

*互換性*

* SQLite schema 20、archive形式``marginalis-archive-17``、MCP tool schema、OAuth scope、
OAuth metadataとendpoint、NixOSのoptionと環境変数は変わらない。既存のclient、authorization grant、
access token、refresh tokenもそのまま使えるため、MCPクライアントを接続し直す必要はない。
* REST APIへ``DELETE /api/v3/mcp-authorizations/{client_id}/scope-ceiling``を追加した。既存の
endpointの要求と応答は変えていない。
* 上限を広げても既存tokenへ権限は追加されない。追加した操作を使うには、これまでどおりクライアント側で
OAuth再認可を行う。
* 閲覧画面の表示だけが変わる。ノートの本文、SQLite schema、archive形式、REST API、MCP tool schemaは
変わらないため、保存済みのノートを書き直す必要はない。

[[0320--2026-08-05]]
== 0.32.0 — 2026-08-05

*破壊的変更*

* 書誌情報の取込元、外部項目との対応、前回取込時の基準を保存するため、SQLite schemaを20、
archive形式を``marginalis-archive-16``へ更新した。v0.31.0でarchive 15を書き出し、v0.32.0の
``migrate-archive``でarchive 16へ変換してから、空の``dataDir``へ取り込む必要がある。
MCPのclient登録とtokenはarchiveへ含まれないため、更新後はMCPクライアントを接続し直す。

*追加*

* Zoteroなどが書き出したCSL-JSON項目配列を、書誌ライブラリーで事前確認してから一括で取り込める
ようにした。新規、外部側だけの変更、Marginalis側だけの変更、双方の変更、重複候補、取込不可を
項目ごとに表示し、双方の内容を比較して処理を選択できる。
* CSL-JSON取込の事前確認と適用をREST APIへ追加した。取込元と外部項目の対応を保存するため、同じ
取込元からの再取込では前回の内容を基準に双方の変更を判定できる。

*改善*

* 取り込みは選択した計画全体を一つのtransactionで保存する。事前確認後に書誌ライブラリーが変わった
場合は全体を競合として拒否し、一部だけを保存しない。外部側の値を採用しても既存のcitation keyを
維持し、入力から消えた書誌情報を自動削除しない。
* CSL-JSONファイルの件数、全体と項目ごとの大きさ、文字列、項目名、入れ子の深さを制限し、取り込めない
項目は入力位置と理由を示す。DOI、ISBN、PMID、PMCID、URL、題名の一致は重複候補として提示するだけで、
自動的には統合しない。

*互換性*

* AdocWeave package版0.27.0とnote profile版5を維持する。archive 7から15までの対応する形式は
``migrate-archive``でarchive 16へ変換できる。既存のMCP書誌toolは1件または最大100件の登録操作として
維持し、ファイル単位の事前確認付き取り込みはWeb UIとREST APIで提供する。

[[0310--2026-08-05]]
== 0.31.0 — 2026-08-05

*破壊的変更*

* ノートの作成経路と人手確認記録を保存するため、SQLite schemaを19、archive形式を
``marginalis-archive-15``へ更新した。v0.30.1でarchive 14を書き出し、v0.31.0の
``migrate-archive``でarchive 15へ変換してから、空の``dataDir``へ取り込む必要がある。
MCPのclient登録とtokenはarchiveへ含まれないため、更新後はMCPクライアントを接続し直す。
* 文書書庫を``marginalis-documents-2``へ更新し、作成経路、人手確認記録、書き出し時の正本文・所有者・
ACLを結び付ける``state_sha256``を追加した。旧形式の文書書庫は取り込めないため、必要な場合は
v0.31.0で改めて書き出す。

*追加*

* ノートを最初に保存した入口を``web``、``rest``、``mcp``として記録するようにした。旧archiveから
移行したノートは根拠のない値を補わず``unknown``とする。Web UI、REST API、MCPで作成経路を表示し、
RESTとMCPの一覧では完全一致で絞り込める。
* 所有者がWeb UIから現在のrevisionを確認済みにできるようにした。新しいノートは``pending``、
旧archiveから移行したノートは``unknown``とし、本文、ACL、削除状態、復元によってrevisionが変わると
``pending``へ移る。共有先には確認者の識別情報を返さず、MCPには確認状態を変更するtoolを提供しない。

*改善*

* 文書書庫を変更せずに取り込んだ場合はrevisionと人手確認状態を維持し、本文、所有者またはACLを
変更した場合はrevisionと更新日時を進めて確認待ちへ移すようにした。``state_sha256``は外部編集の
検出に使う値であり、署名や改ざん防止の証明としては扱わない。

*互換性*

* AdocWeave package版0.27.0とnote profile版5を維持する。archive 7から14までの対応する形式は
``migrate-archive``でarchive 15へ変換できる。作成経路は接続方法の記録、人手確認は特定revisionを
利用者が確認した記録であり、内容の正しさやAI利用の有無を証明しない。

[[0290--2026-08-05]]
== 0.29.0 — 2026-08-05

*破壊的変更*

* MCPクライアントごとの認可履歴、scope上限、最終利用日時を保存するため、SQLiteスキーマを18へ

持つscopeと今回の操作に必要なscopeを一つの``WWW-Authenticate`` challengeで示し、追加認可できる。

直ちに失効する。上限を広げても既存tokenへ権限は追加せず、OAuth再認可を必要とする。
* ``GET /api/v3/mcp-authorizations``と、クライアント別上限を変更する
``PUT /api/v3/mcp-authorizations/{client_id}/scope-ceiling``を追加した。既存の接続取消APIと同様に、
認証中の利用者本人に属する認可だけを対象とする。

*互換性*

* archive ``marginalis-archive-14``、AdocWeave package版0.27.0、note profile版5を維持する。
v0.28.1で書き出したarchiveは変換せずに検証・復元できる。

[[0250--2026-08-03]]
== 0.25.0 — 2026-08-03

*破壊的変更*

* MCPのAuthorization Serverを内蔵した。外部のAuthorization Serverは使用しない。判断の内容は
xref:docs/adr/0007-mcpのauthorization-serverを内蔵する.adoc#top[MCPのAuthorization Serverを内蔵する]に
記録した。利用者の認証は従来どおりKanidmが行い、MCPのclient登録、認可code、access token、
refresh tokenはMarginalisが管理する。更新前に発行したMCPのtokenとclient登録は移行しないため、
更新後にMCPクライアントの接続を作り直す。
* MCPの有効・無効を``MARGINALIS_MCP_ENABLE``で指定するようにした。値は``true``または``false``とし、
それ以外は起動時に拒否する。外部Authorization Server用の``MARGINALIS_MCP_AUTHORIZATION_ISSUER``、
``MARGINALIS_MCP_UPSTREAM_ISSUER_CLAIM``、``MARGINALIS_MCP_UPSTREAM_SUBJECT_CLAIM``、
``MARGINALIS_MCP_GROUPS_CLAIM``は廃止した。NixOSモジュールが値を組み立てるため、
``services.marginalis.mcp.enable``を使う場合は設定の変更が不要です。
* NixOSモジュールの``services.marginalis.mcp.authorization``を削除した。この設定を書いている場合は
取り除く。issuerと各endpointは``baseUrl``から自動的に導く。
* SQLiteスキーマを13から15へ更新した。MCPのclient、認可code、tokenを保存する表と、認可要求で
``redirect_uri``が指定されたかを記録する項目を追加したため、
稼働中の旧データベースファイルはそのまま使用できない。更新前に``export-archive``を実行し、
新しい版で空の``dataDir``へ``import-archive``する。archiveの形式は13のまま変わらない。
* MCPの起動条件を変更した。認可に外部サービスを使わなくなったため、起動可否はKanidmの
discoveryだけで決まる。以前は外部Authorization Serverのdiscoveryに失敗すると起動しなかった。

*追加*

* コードブロックの言語として``python``を指定できるようにした。``get_note_profile``の
``allowed_source_languages``にも同じ値を追加し、執筆プロファイルの版を14へ上げた。
* MCPクライアントの登録方式としてClient ID Metadata Documentに対応した。HTTPSのURLを``client_id``と
して使い、そのURLでclient名と``redirect_uris``を公開する方式です。事前登録を必要とせず、DCRとは
登録上限を分けて管理する。有効な文書だけをHTTPのcache指示に従って保持し、失敗や不正な文書は
保持しない。同じclientへの同時要求は一つの取得結果を共有し、全体の同時実行数と取得回数、DNSを
含む処理時間を制限する。認可GET内では解決結果を検証にも使い、不必要な再取得を行わない。

== 0.1.0 — 2026-07-23

研究室内で REST API と MCP を実運用するための最初のリリースです。``/api/v1`` の OpenAPI
API 仕様とデータフォーマット v1 の互換性保証をこのバージョンから開始した。

*追加*

* OIDC ログイン、root 管理、ユーザーへの直接 ACL、監査ログ。
* AsciiDoc 正本を用いる REST ノート CRUD、FTS5 検索、``ETag`` による条件付き更新、物理削除。
* OAuth Authorization Code \+ PKCE で保護された MCP ツール（検索・取得・参照一覧・作成・
更新・削除）。
* OpenAPI 3.1 仕様、NixOS モジュール、バックアップ・復元、検索・参照データの再構築、root 監査の
365 日保持。

*セキュリティ*

* Cookie を伴う変更操作で、CSRF トークン・公開オリジン・Fetch Metadata を検証する。
* root 管理ルーターを通常 API から分離し、プロキシの forwarded クライアント IP ヘッダーを
信頼しない。

*修正*

* NixOS のランタイム VM リリーステストへ ``sqlite3`` CLI を含め、root 資格情報の検証を実行
できるようにした。

*既知の制約*

* Web UI、SMTP、招待、ユーザー再有効化、グループ ACL、専用管理オリジン・mTLS は含まれない。
* 実際の Kanidm と MCP クライアントを使う受入確認は、秘密情報を CI へ置かずに手動で行う。
* ``/api/v1`` への破壊的変更は、新しいバージョンパスと非推奨告知を伴って行う。

= Marginalisへの参加

[#top]
この文書は、AIエージェントを含む開発参加者向けの案内です。開発環境、検証、GitHubでの詳しい
作業手順は xref:docs/developer-guide/development.adoc#top[GitHubを使う開発手順]、システムの仕様や運用手順は
xref:docs/README.adoc#top[資料案内]を参照してください。

== 作業の始め方

[arabic]
. 作業前に関連するGitHub Issueと現行仕様を確認します。
. 最新の``main``から目的が分かる作業ブランチを作成します。
. 既存の形式とコンポーネントの役割分担に従い、変更に対応する文書とテストも更新します。
. 関連する検証を実行し、目的、主な差分、検証結果をPull Requestへ記載します。
. Pull Requestをmerge queueへ投入し、``main``へマージします。``main``へ直接pushしません。
queueが最新の``main``と組み合わせて必須チェックを実行するため、作業ブランチを事前に
``main``へ揃える必要はありません。操作の詳細は
xref:docs/developer-guide/development.adoc#top[GitHubを使う開発手順]を参照してください。

新しい作業項目と完了条件はGitHub Issuesで管理します。機能の修正、改善、追加では、
Issue Formに現在と理想の動作例を記載してください。設計判断を長期に参照する場合は、
実装Issueとは別に xref:docs/developer-guide/documentation.adoc#top[文書管理方針]に従ってADRを追加します。

Pull Requestには、変更の目的、利用者や運用者が理解できる主な差分、実行した検証、互換性と
移行への影響、セキュリティーと運用への影響、関連Issueを記載します。確認が不要な項目は、
省略せず該当しない理由を記載してください。

== 基本検証

検証コマンドとその使い分けは
xref:docs/developer-guide/development.adoc#top[GitHubを使う開発手順]を正本とします。開発中は
``cargo make verify``、push前は``cargo make pre-push``を実行します。公開前の検証と受入は
xref:docs/developer-guide/release.adoc#top[リリース手順]に従います。

== セキュリティー

秘密情報、個人情報、実際のCookie、token、認可code、client secret、ノート本文をIssue、
Pull Request、ログ、テストの成果物へ記録しません。脆弱性や認証情報の漏えいが疑われる場合は、
公開Issueを作成せず、リポジトリ所有者へ非公開経路で連絡してください。

# v0.3.0 運用契約

v0.3.0 は新規の空 SQLite database を対象とする破壊的リリースである。v0.2 の
`dataDir`、root、登録ポリシー、`/api/v1`、ファイル正本を引き継がない。

## NixOS 設定

```nix
services.marginalis = {
  enable = true;
  baseUrl = "https://notes.example.test/marginalis";
  listenAddress = "127.0.0.1:3000";
  backupDirectory = "/srv/marginalis-backups";
  oidc = {
    issuerUrl = "https://id.example.test/oauth2/openid/marginalis";
    clientId = "marginalis";
    clientSecretFile = "/run/secrets/marginalis-oidc-client-secret";
    caCertificateFile = "/run/secrets/marginalis-kanidm-ca.pem";
    membershipApiUrl = "https://id.example.test";
    membershipTokenFile = "/run/secrets/marginalis-kanidm-membership-token";
  };
  mcp.enable = true;
};
```

`clientSecretFile` と `membershipTokenFile` は systemd credential として渡される。値を Nix store、
環境変数、ログへ書き出してはならない。`membershipTokenFile` は person entry の `memberof` だけを
読める read-only Kanidm service-account API token とする。`membershipApiUrl` は `issuerUrl` と同じ
origin の Kanidm API を指す必要がある。reverse proxy は `/auth/`、`/api/`、
`/mcp`、`/.well-known/`、`/oauth/` を同一オリジンへ転送する。サブパスを使う場合、外部 URL の
接頭辞を upstream へ渡す前に除去する。

Kanidm 1.10 の OIDC client は `server-users` と `server-admins` を含む group claim を返すよう
構成する。`server-users` 非所属の主体はログインできず、`server-admins` は全ノートを閲覧できる。
`baseUrl` にサブパスを含める場合、Web UI、OIDC login 復帰、MCP authorization の browser redirect は
その接頭辞を含む。proxy は外部の接頭辞だけを除去し、アプリケーションへは内部 route を渡す。

内部 CA で Kanidm を TLS 終端する場合は `caCertificateFile` に PEM trust anchor を指定する。この CA は
OIDC Discovery、token exchange、membership API のすべてに適用される。公開 CA の場合は省略できる。

## 日常運用

- `GET /api/v2/health` は公開 liveness endpoint である。
- OIDC Discovery が一時的に失敗しても service は起動を維持する。この間はログインを開始できず、
  session と MCP token の membership 再確認も freshness の期限後に fail closed となる。
  OIDC Discovery は各ログイン開始時に再試行するため、IdP の復旧後に service を再起動する必要はない。
- `marginalis-purge-deleted.timer` は 30 日を過ぎたソフトデリート済みノートを日次で物理削除する。
- `marginalis-backup.service` は `backupDirectory` に時刻付きディレクトリを作り、
  `marginalis-v3-archive.json` を保存する。service と競合させるため、実行は週末の停止枠で行う。
  backup 完了後も `marginalis.service` は停止したままなので、確認後に運用者が明示的に再開する。
- archive は `marginalis import-archive --input <absolute-file>` で空の v3 SQLite database へ
  取り込める。定期復元試験は v0.3.0 の release gate 外である。

## MCP OAuth

MCP endpoint は `POST B/mcp` である。Protected Resource Metadata は
`B/.well-known/oauth-protected-resource/mcp`、Authorization Server Metadata は
`B/.well-known/oauth-authorization-server` に置く。MCP client は Dynamic Client Registration
（`POST B/oauth/register`）でパブリック client を作成し、Authorization Code + PKCE S256 を使う。

アクセスには `notes:read`、`notes:write`、`notes:delete` の scope と、通常のノート ACL の両方が
必要である。`DELETE /api/v2/mcp-authorizations/{client_id}` は Cookie session、Origin、CSRF token を
必要とし、その client の access token と refresh token を失効させる。

## v0.3.0 release gate

1. Kanidm 1.10、TLS、サブパスで `server-users` / `server-admins` の認可を確認する。
2. ChatGPT、Claude Code、Codex CLI で MCP OAuth login、read/write、認可取消を確認する。
3. NixOS module による空 database からの配備と backup destination を確認する。

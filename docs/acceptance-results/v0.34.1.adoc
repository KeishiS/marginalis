== 今回の確認で重点を置く点

この版は、MCPクライアントへ許可するscopeの上限に関する2つの不具合を直します。新しい機能を加える
ものではないため、確認の中心は「上限の扱いが利用者から見て一貫していること」です。

*上限を超える権限の表示*: クライアント別の上限を``notes:read``だけに設定した状態で、``notes:write``も
要求するクライアントから認可します。同意画面で``notes:write``を選べないこと、要求されたが許可できない
権限として理由が示されることを確認します。要求された権限がすべて上限を超える場合は、同意画面が出ずに
クライアントへ``invalid_scope``が返ることも確認します。

*上限内の権限の付与*: 同意画面で選んだ権限がそのままtokenへ記録され、MCPアクセス設定の付与済みscopeにも
反映されることを確認します。承認した権限が黙って減らないことが要点です。

*クライアント別上限の解除*: MCPアクセス設定で「上限を解除」を選び、未設定へ戻ることを確認します。解除
しても既存の接続とtokenが残ること、その後の再認可でサーバーが対応する全scopeを許可できることを確認
します。

*同意していない権限を含む上限の設定*: 解除せずに、まだ同意していない権限を上限へ追加できることを確認
します。上限を広げただけでは既存tokenへ権限が増えないこと、追加した操作にはクライアント側の再認可が
必要であることも確認します。

*上限を狭めたときの失効*: 上限を狭めると、新しい上限を超えるtoken familyだけが直ちに失効し、上限内の
接続は維持されることを確認します。

*既存接続の維持*: v0.34.0のdatabaseをそのまま引き継いで配備し、既存のMCP access tokenとrefresh tokenが
そのまま使えることを確認します。この版ではMCPクライアントの再接続を不要とします。

*公開契約の差分*: MCP tool schema、NixOS moduleのoption、SQLite schema、archive形式、OAuth metadataと
scopeについて、v0.34.0タグと比べて意図しない差分がないことを機械的に確認します。OpenAPIには
``DELETE /api/v3/mcp-authorizations/{client_id}/scope-ceiling``の追加だけがあることを確認します。

利用者、Cookie、token、認可code、PKCE verifier、実際のノート本文や書誌情報は記録しません。

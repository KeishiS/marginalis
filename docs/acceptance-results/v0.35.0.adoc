== v0.34.1から統合した経緯

MCPのscope上限に関する2つの修正は、当初v0.34.1として公開する予定でした。人手受入を終えて
公開判定を``公開可``とした後、公開前のrelease gateが新しく公開された脆弱性情報
（CVE-2026-59870、GHSA-5p4m-2wfm-xmqj）で失敗しました。``stylelint``が間接的に取り込む
``js-yaml``を修正版へ上書きして解消しましたが、その後にWeb UIの改善を``main``へ取り込んだため、
v0.34.1の内容だけを指すコミットが``main``の先端でなくなりました。release gateはタグ対象が
``main``の先端であることを求めるため、v0.34.1を単独で公開できません。

そのため、v0.34.1の内容をv0.35.0へ統合します。scope上限に関する確認は2026-08-06に実施済みで、
その結果を下表へ引き継ぎます。引き継いだ項目の対象は、当時のv0.34.1候補である
https://github.com/KeishiS/marginalis/pull/365[Pull Request \#365]の先端
``7aa7dfdcf8318a44828770a48e5f50ab7c000dc1``（tree ``03fc20d13949bcc8f9e40b17d31924d1f90d3a9f``）です。
このcommitは``main``の履歴に残らないため、``refs/pull/365/head``から取得します。

引き継いだ確認の後にscope上限の実装は変更していません。v0.35.0で加えたのはWeb UIの表示と
``js-yaml``の上書きだけです。``js-yaml``は``stylelint``の依存であり、配布するプログラムには含まれません。

== 今回の確認で重点を置いた点

この版はWeb UIの表示を改善します。ノートの本文、保存形式、公開契約は変えないため、確認の中心は
「読みやすくなったこと」と「これまでできた操作がそのままできること」です。

*閲覧本文の見出しと本文の大きさ*: 文書題名、``==``の章見出し、``===``の節見出し、``====``の項見出し、
本文が段階的に小さくなることを確認しました。章見出しが題名と同じ大きさに見えないこと、本文が
小さすぎないことが要点です。

*文章の行の長さ*: 広い画面で段落が画面いっぱいまで伸びず、折り返し位置を追える幅に収まることを
確認しました。同じ画面で、表、コードブロック、数式は従来どおり広い横幅を使えることも確認しました。

*定義リストの表示*: 用語と説明を含むノートを開き、用語が太字で示され、説明が用語より内側から
始まることを確認しました。1組の用語と説明が、次の組と区別できることも確認しました。

*狭い画面からの移動*: 360px相当の幅で、ヘッダーの「メニュー」からノート、書誌、関係の図、設定へ
移動できることを確認しました。「新規ノート」がメニューの外から直接押せることも確認しました。広い画面では
メニューボタンが出ず、移動先が横に並ぶことを確認しました。

*現在位置の表示と押せる大きさ*: いま開いている画面が見た目で分かること、支援技術へも現在位置が
伝わることを確認しました。移動先とボタンが指で押せる大きさであることも確認しました。

*狭い画面の横方向のはみ出し*: 一覧、閲覧、編集、設定の各画面で、画面全体が横へはみ出さないことを
確認しました。メニューを開いた状態でも確認しました。表、コードブロック、数式が要素の内側で
横スクロールすることも確認しました。

*既存databaseからの更新*: v0.34.0のschema 20を残したままv0.35.0を配備し、起動、OIDCログイン、
Web UI、既存のノートの表示を確認しました。

*公開契約の差分*: OpenAPI、MCP tool schema、NixOS moduleのoption、SQLite schema、archive形式、
OAuth metadataとscopeについて、v0.34.0タグと比べた差分が
``DELETE /api/v3/mcp-authorizations/{client_id}/scope-ceiling``の追加だけであることを機械的に確認しました。

利用者、Cookie、token、認可code、PKCE verifier、実際のノート本文や書誌情報は記録していません。

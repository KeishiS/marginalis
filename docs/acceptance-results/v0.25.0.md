## 今回の確認で重点を置いた点

MCPのAuthorization Serverを内蔵したため、認可の経路全体を実際のクライアントで確認します。
ChatGPT、Claude Code、Codex CLIのそれぞれで、接続の作成、同意画面での許可、ノートの閲覧と更新、
接続の取消までを通します。Client ID Metadata Documentを使うクライアントとDynamic Client
Registrationを使うクライアントの両方を含めます。

認可の取消では、取り消した直後に既存のaccess tokenとrefresh tokenがどちらも拒否されることを
確認します。外部サービスに依存しないため、取消から失効までの待ち時間は生じない想定です。

配備では、`services.marginalis.mcp.authorization`を書かない設定で起動できること、
`MARGINALIS_MCP_ENABLE`に`true`と`false`以外を与えると起動が止まることを確認します。

更新経路では、schema 13のデータベースから`export-archive`で書き出したarchive 13を、空の
schema 15へ`import-archive`で取り込み、ノート、所有者、ACL、参照、削除状態、revisionが一致する
ことを確認します。MCPのclientとtokenはarchiveへ含まれないため、更新後に接続を作り直します。

利用者、Cookie、token、認可code、client secret、実際のノート本文や書誌情報は記録しません。

## 今回の確認で重点を置く点

初回接続では`notes:read`だけが提示され、更新時には既存の`notes:read`と不足する`notes:write`が一つの
challengeに含まれることを確認します。追加認可を拒否しても元の閲覧権限が維持され、同意した場合だけ
新しいtokenで更新できること、削除scopeが削除操作まで自動で追加されないことも確認します。

設定画面では、認証中の利用者が自分で認可したクライアントだけを確認できることを確認します。scope上限を
狭めた場合は範囲外の接続が直ちに失効し、広げただけでは既存tokenへ権限が追加されないこと、クライアントが
要求したことのないscopeを設定できないことを確認します。

SQLite schema 18へは旧databaseを直接引き継がず、v0.28.1で書き出したarchive 14を空の`dataDir`へ
取り込みます。ノート、ACL、参照、削除状態、revision、数式マクロ設定、書誌情報が一致し、MCP clientと
tokenは移行されないことを確認します。

利用者、Cookie、token、認可code、PKCE verifier、実際のノート本文や書誌情報は記録しません。

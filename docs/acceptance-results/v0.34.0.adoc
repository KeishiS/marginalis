== 今回の確認で重点を置く点

この版では、内蔵Authorization Serverのソースを専用リポジトリへ移し、Marginalisは公開済みv0.1.0の
完全なcommit SHAを固定したGit依存として取り込みます。目的は配布と保守の責務を分けることであり、
実行時の構成は変えません。したがって確認の中心は、新しい機能ではなく「変わっていないこと」です。

*既存の状態をそのまま引き継げること*: v0.33.0のschema 20を残したままv0.34.0を配備し、起動、
OIDCログイン、Web UIを確認します。既存のMCP access tokenがそのまま使えること、既存のrefresh tokenを
交換できること、交換前のrefresh tokenを再利用したときにtoken family全体が失効することを確認します。
client単位の取消と再認可、利用者全体とclient別のscope上限も従来どおりであることを確認します。

*実クライアントからの接続*: ChatGPT、Claude Code、Codex CLIから新規に接続し、``notes:read``、
``notes:write``、削除の順に段階的な認可が提示されることを確認します。追加の認可を拒否しても、
すでに得ている読み取り権限が維持されることも確認します。

*archiveとNixOS*: v0.33.0のarchive 17を変換せずに``validate-archive``と``verify-restore``へ通し、
空のschema 20へ取り込みます。再度書き出したarchiveがarchive 17であることも確認します。NixOSでは、
追加のserviceやportが生じていないことを確認します。

*公開契約の差分*: OpenAPI、MCP tool schema、NixOS moduleのoption、SQLite schema、archive形式、
OAuth metadataとscopeについて、v0.33.0タグと比べて意図しない差分がないことを機械的に確認します。

利用者、Cookie、token、認可code、PKCE verifier、実際のノート本文や書誌情報は記録しません。

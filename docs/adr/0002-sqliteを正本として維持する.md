# SQLiteを正本として維持する

- 状態: 採用
- 日付: 2026-07-29

## 背景

Marginalisは単一のNixOSホストで、同時利用者10名程度、約1,000ノートを扱うことを想定しています。
SQLiteには、完全なAsciiDoc文書、所有者、ACL、参照、削除状態、Webセッション、OIDCログイン試行を
保存します。ノート更新では認可、期待する`revision`、本文、文書から導出した題名とタグ、参照を一つの
トランザクションで変更します。閲覧画面も、本文、実効アクセス水準、参照先、参照元を一つの
読み取り時点から取得します。

用途別の保存インターフェースは`NoteQueryRepository`、`NoteCommandRepository`、
`NoteAclRepository`、`WebSessionRepository`などへ分かれています。業務処理はSQLiteの型を
公開境界へ出しません。一方、配備、診断、バックアップ、復元、同時書き込み、NixOS試験はSQLiteの
具体的な性質を利用しています。

Issue #20では、将来の可能性だけを理由にPostgreSQL実装と二種類の運用経路を保守すべきかを
再検討しました。

## 決定

SQLiteを唯一の正本として維持し、現時点ではPostgreSQLへ対応しません。

- 現行規模では、一つのサーバープロセスと、書き込みログを別ファイルへ記録するSQLiteのWAL方式を
  維持します。
- 用途別の保存インターフェースは、業務処理とSQLite実装の境界を明確にするために維持します。
  将来のデータベース製品を想定した共通SQL層は作りません。
- 書き込みの条件、失敗分類、再試行の要否は操作ごとに設計します。すべてのSQLiteエラーを
  一律に再試行しません。
- データベース容量だけを移行条件にしません。バックアップ、アーカイブ検証、復元が定めたRPOとRTOを
  満たせるかで判断します。RPOは許容できるデータ損失時間、RTOは復旧目標時間です。
- PostgreSQLを採用する場合も二重書き込みは行わず、検証済みアーカイブを介して空の正本へ移行します。

## 結果

開発、CI、NixOS運用、障害診断、バックアップ、復元を一つの保存方式へ集中できます。SQLite固有の
条件付き更新や一貫した読み取りを明示して利用でき、二種類のSQL方言を共通化するために
認可とトランザクションの意味を弱めません。

複数ホストで同時に書き込む構成や、単一ホスト障害中も書き込みを継続する構成は提供しません。
これらが必要になった場合は、PostgreSQLの追加だけでなく、サーバー間の状態、Webセッション、配備、
監視、バックアップ、復元をまとめて再設計する必要があります。

## 代替案

### PostgreSQLを直ちに追加

複数のサーバープロセスや高可用性へ進みやすくなりますが、現行要件には不要です。データベース構造、
SQL、検索、同時実行、診断、秘密情報、バックアップ、復元、NixOS試験を二組保守する負担が
先に発生するため、
採用しません。

### SQLを共通化した一つの保存実装

重複するコードを減らせますが、SQLiteとPostgreSQLで異なるロック、トランザクションの分離水準、
全文検索、診断、バックアップの性質を隠します。認可と`revision`を同じトランザクションへ
拘束する責務を
読み取りにくくするため、採用しません。

### SQLiteとPostgreSQLへの二重書き込み

段階的に移行できますが、部分失敗時に二つの正本が食い違います。複数のデータベースをまとめて
確定する仕組みまたは複雑な復旧処理が必要になるため、採用しません。

## 再検討条件

次のいずれかが実際の要件または再現可能な測定結果として成立した場合に再検討します。

- 一つの正本へ書き込む複数のMarginalisサーバープロセスまたは複数ホストの必要性
- 単一ホスト障害中も書き込みを継続する高可用性の必要性
- SQLiteのバックアップとアーカイブ復元では満たせないRPOまたはRTO
- 1,000ノートと10の同時Webセッションを使う代表負荷で、問い合わせとトランザクションを
  改善してもデータベースのロックによるHTTP 5xxが発生する状態
- 同じ代表負荷で、読み取りの95%が250 ms、書き込みの95%が500 ms以内という判断基準を、
  SQLiteの調整後も継続して満たせない状態
- SQLiteファイルと保全世代を置けない容量、または既存PostgreSQL基盤への統合が必須となる運用要件

再検討時は、各保存実装で同じ認可、`revision`、削除、参照、Webセッション期限を検査する適合性試験、
SQLiteからの移行と切戻し、PostgreSQLのNixOS配備、秘密情報、診断、バックアップ、復元を
先に設計します。

# AsciiDoc編集画面

この文書は、Web UIで長いAsciiDoc文書を編集する利用者と、編集機能を保守する開発者を対象に、
表示方式、入力操作、既知の制約を説明します。保存と競合のREST契約は[REST API](rest-api.md)、
編集基盤の採用理由は[CodeMirror採用判断](adr/0003-codemirrorをasciidoc編集基盤に採用.md)を
優先してください。見たまま編集、共同編集、添付ファイルは対象外です。

## 表示方式

編集画面は次の三つの表示を切り替えます。切替では入力欄を作り直さないため、入力位置、選択範囲、
編集履歴、入力欄のスクロール位置を維持します。

| 表示 | 用途 |
| --- | --- |
| 執筆 | 利用可能な横幅を本文入力に使用 |
| 分割 | 入力欄とサーバー生成プレビューを左右に表示 |
| プレビュー | 利用可能な横幅をプレビューに使用 |

幅が60rem以下の画面では分割を使用せず、執筆とプレビューを明示的に切り替えます。分割表示では
「執筆欄の幅」で左右の比率を30%から70%まで変更できます。

「相対位置でスクロールを同期」を有効にすると、入力欄とプレビューについて、それぞれの
スクロール可能な長さに対する割合を合わせます。AsciiDocの一行がプレビューの一要素に対応するとは
限らず、見出し、表、コード、数式の高さも異なるため、同じ内容が必ず横に並ぶ機能ではありません。
正確な対応が必要な場合は、診断の「入力位置へ移動」を使用します。

## 入力操作

入力欄は行番号、長い行の折り返し、検索、元に戻す操作、やり直す操作を提供します。通常の
CodeMirrorキーボード操作に加えて、次の操作を固定しています。

| 操作 | 結果 |
| --- | --- |
| `Ctrl+S`または`Command+S` | 現在の文書を明示的に保存 |
| `Tab` | タブの挿入または選択した複数行の字下げ |
| `Shift+Tab` | 現在行または選択した複数行の字下げを解除 |
| `Ctrl+F`または`Command+F` | 文書内検索 |

日本語IMEで変換している間は、保存とプレビュー更新を開始しません。変換を確定すると、確定した
完全な文字列を基にプレビュー更新を再開します。

## 解析とプレビュー

CodeMirrorはAsciiDoc文書を文字列として編集します。AsciiDocの正しさをブラウザー内で独自に
判定せず、MarginalisがAdocWeaveを使って解析し、プレビューHTMLと診断を返します。この分担により、
未知の文書属性や将来追加する記法も入力時に失われません。

プレビューは入力が止まってから350ミリ秒後に更新します。更新に失敗した場合も、最後に成功した
プレビューを残します。診断から「入力位置へ移動」を選ぶと、プレビュー表示中でも執筆表示へ
切り替え、対象の文字列を選択して見える位置までスクロールします。

執筆表示中もプレビューHTMLの生成を続けますが、MathJaxによる数式の組版はプレビューを表示する
時点で行います。このため、非表示中に生成が完了した数式も、プレビューまたは分割へ切り替えた後に
組版されます。

プレビューと閲覧画面では、すべてのコードブロックへ1から始まる行番号を表示します。
`[source,言語名,linenums,start=開始行]`で開始行を指定した場合は、その番号から表示します。

## 検証上限

ブラウザー試験では、UTF-8で512 KiB以下の5,000行の固定文書について、貼り付け、表示切替、
キーボード保存が完了することを確認します。320px幅と通常のデスクトップ幅では固定画像を比較し、
主要操作と入力欄が横方向へ失われないことを検査します。デスクトップ幅ではライト表示とダーク表示の
両方を比較します。本番と同じCSPを適用し、CodeMirrorの基礎CSSと行番号gutterの配置も検査します。

production用`editor.js`は600,000バイトを上限とします。この上限はCodeMirror導入時の
545,570バイトに余裕を加えた値です。上限を超える場合は、機能追加だけを理由に広げず、配信経路の
分割または依存の削減を先に検討します。

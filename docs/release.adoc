= リリース手順

[#top]
この文書は、各バージョンに共通するリリース手順を定めます。バージョンごとの互換性と移行方法は
xref:../CHANGELOG.adoc#top[変更履歴]を確認してください。変更履歴にデータの退避や``dataDir``の初期化が
指示されている場合だけ、その手順を実施します。

== 事前検証

[arabic]
. Cargo workspaceの版と変更履歴を更新し、 xref:acceptance.adoc#top[受入基準]の版別結果を作成して索引へ
追加します。確認前の項目は``未実施``、``公開判定``は``未判定``とします。
. 作業ブランチで``cargo make verify``を実行します。公開版、変更履歴、受入結果、Nix packageの
版情報も``verify``内の``release-metadata``で検査します。
. 外部のGit依存が意図した公開版を指していることを確認します。``cargo make shared-authorization-server``が、
共有Authorization Serverの2 crateについて、版が同じであること、同じリポジトリの40桁の完全SHAから取得して
いること、``Cargo.lock``の取得元が宣言と一致すること、``flake.nix``に取得ハッシュがあることを検査します。
指しているSHAが上流の公開済みタグに対応することは、次のように確認します。
+
[source,sh]
----
gh api repos/KeishiS/mcp-authorization-server/git/ref/tags/<tag> --jq '.object.sha' |
  xargs -I{} gh api repos/KeishiS/mcp-authorization-server/git/tags/{} --jq '.object.sha'
grep -n 'rev =' Cargo.toml
grep -n 'mcp-authorization-server' Cargo.lock flake.nix
----
+
上流の未公開コミットや、タグが付いていないコミットを指したまま公開しません。
. Kanidm 1.10、TLS、サブパスを使うNixOSのE2Eテストを実行します。
. ChatGPT、Claude Code、Codex CLIからMCPへ接続し、読み取り、書き込み、認可取消を確認します。
. 空のデータベースからNixOSへ配備できること、バックアップ先、削除用タイマーを確認します。
. 最新のアーカイブを、本番から隔離した空のデータベースへ復元します。
. OpenAPI、MCP、NixOS、受入資料が同じ仕様を説明していることを確認します。
. 版別結果の自動・人手項目へ実施日、結果、証跡を記録します。
``未実施``または``失敗``がある場合は、公開を止めるか、公開できる理由と残る影響を同じ結果へ
記録します。版別結果の``公開判定``は、確認中は``未判定``、公開しない場合は``公開停止``、
公開できる場合だけ``公開可``とします。
. 人手受入で配備したcommitとtree、および最終リリースのタグ参照を版別結果へ記録します。
人手受入後に``CHANGELOG.adoc``と版別結果以外を変更した場合は、新しいcommitを配備して人手受入を
やり直します。記録する値と変更範囲は次のコマンドで確認します。rebase方式でマージした場合は、
人手受入対象のcommitがPull Requestの履歴から取得できる間に確認します。
+
[source,sh]
----
git show -s --format='%H %T' <人手受入対象commit>
git diff --name-only <人手受入対象commit> HEAD -- . \
  ':(exclude)CHANGELOG.adoc' \
  ':(exclude)docs/acceptance-results/v<版>.adoc'
----
+
2つ目のコマンドが何も出力しないことを確認します。記録形式は
xref:acceptance.adoc#top[受入基準]に従います。
. ``公開判定``を``公開可``へ変えるときは、同じ変更で``CHANGELOG.adoc``の対象版に判定日を
``YYYY-MM-DD``形式で記録します。``公開可``と``未公開``が併存する場合は、通常の``verify``も失敗します。
. 受入結果は、個々の確認が終わるたびにリリース用Pull Requestへ追記せず、人手確認をすべて
終えた後に一度だけ更新します。自動検証の証跡には、実行ごとに変わるCIのURLではなく、
リリース用Pull RequestのURLを記録します。

== Pull Request

[arabic]
. Pull Requestを作成し、目的、主な差分、検証結果を記載します。
. 受入結果を確定した最後のコミットに対して、必須チェックが成功したことをPull Request上で
確認します。成功したCIの情報を同じブランチへ書き戻しません。書き戻すと先端コミットが変わり、
同じ検査を再実行する必要が生じます。
. 必須チェックとレビューの完了後にrebase方式で自動マージされるよう設定します。

== リリース検証とタグ

[arabic]
. 版別受入結果を含むPull Requestが``main``へマージされた後、先端のコミットで
``release-gate``ワークフローを手動実行します。
. 版別受入結果の``公開判定``が``公開可``であることを確認します。
. ``release_tag``には作成予定のタグを入力し、検証の成功を確認します。
. 検証した``main``の先端へリリースタグを作成してプッシュします。
. タグのプッシュによって再実行される``release-gate``も成功することを確認します。
. 公開後に最終リリースのcommitとtreeを版別結果へ補足する場合は、次のコマンドでタグから値を取得します。
+
[source,sh]
----
git rev-parse 'refs/tags/v<版>^{commit}'
git show -s --format=%T 'refs/tags/v<版>^{commit}'
----

Pull Request本文は作業中の状態を伝える記録であり、公開判断の正本ではありません。検証状態が
``実行中``のまま残っていても、版別受入結果、タグが指すcommit、GitHub Actionsの最終結果を公開判断の
正本とします。公開後に版別結果へ最終commitとtreeを補足する場合は、タグを解決した値を記録します。

日次バックアップ、30世代の保持、四半期の復元確認については
xref:nixos.adoc#top[NixOSでの運用]を参照してください。

# Web UIの画面設計

この文書は、Marginalisのノート一覧、閲覧、編集、共有設定に共通する画面設計を説明します。
個別機能の操作は、[AsciiDoc編集画面](web-ui-editor.md)など、それぞれの機能を説明する文書を
参照してください。

## 目的

画面では、ノートの本文と執筆領域を最も重要な情報として扱います。強い色や影を多用せず、
文字の大きさ、余白、整列によって情報のまとまりと操作の優先順位を示します。

主要な操作にはアクセント色を使い、同じ画面に複数置きません。画面から離れる操作や補助操作には、
背景と境界線だけを使います。削除など取り消しにくい操作には、主要操作とは異なる警告色を使います。

## 共通の画面構成

画面上部には、製品名、ノート一覧、新規ノートへの移動手段を置きます。機能数が少ない間は、
内容のないサイドバーを設けません。画面が狭い場合は製品名と新規作成を残し、一覧への移動は
製品名から行います。

本文領域の最大幅は、画面の用途に応じて変えます。

- 一覧と共有設定: 入力欄と複数の項目を見渡せる幅
- ノート閲覧: 長文の可読性を保ちながら、表、コード、数式へ広い横幅を使える幅
- 編集: CodeMirrorとプレビューを左右に並べられる幅

閲覧画面の本文上部にはnote IDとコピー操作を表示します。コピー結果は文字で示し、
`aria-live`を使って読み上げます。本文領域はデスクトップ相当の画面で最大96remまで広げ、
狭い画面では画面幅に合わせて縮めます。

## 目盛りとCSSの置き場所

色、余白、文字の大きさ、角丸、影、本文幅は`frontend/src/styles/tokens.css`のCSS custom
propertiesで定義します。個別の部品では、この目盛りの変数だけを使います。

余白は`--space-1`から`--space-16`まで、0.25rem刻みの段で選びます。文字の大きさは
`--text-caption`、`--text-small`、`--text-body`、`--text-title`、`--text-heading`のように
用途で選びます。境界線の太さは`--border-thin`と`--border-thick`です。値そのものではなく段を
選ぶため、近い値が少しずつ増えることがありません。

段は、見て区別できる差だけを置きます。0.85remと0.9remのように1px未満しか違わない段は、
選ぶ基準を説明できないため作りません。

CSSは役割ごとに分けます。新しい規則は次の基準で置き場所を決めます。

| ファイル | 置くもの |
| --- | --- |
| `tokens.css` | 目盛りの定義。ここだけは直値で書く |
| `base.css` | 要素の既定、フォーカス表示、動きを減らす設定 |
| `layout.css` | ヘッダー、`main`、画面全体の枠組みと余白 |
| `components.css` | ボタン、入力欄、一覧、通知、診断など画面の部品 |
| `content.css` | AdocWeaveが生成したHTMLの表示 |

画面幅による並び替えは、対象の規則と同じファイルへ書きます。

class名はkebab-caseとし、役割ごとの接頭辞（`page-`、`note-`、`editor-`、`bibliography-`、
`access-`、`conflict-`、`toast-`など）を先頭に付けます。`citation`、`bibliography-anchor`、
`source-block`、`math-latex`などはAdocWeaveが生成するHTMLのclassです。Marginalisが決める
名前ではないため`content.css`へ集め、改名しません。

目盛りから外れた値は`cargo make frontend-verify`のstylelintが拒否します。外部の部品へ合わせる
ためにやむを得ず外す場合は、その行に理由を書きます。

ライト表示とダーク表示は、OSとブラウザーの`prefers-color-scheme`設定に従います。どちらの
表示でも、本文、補助情報、フォーカス、成功、警告、失敗を色だけに依存せず、文字または境界線でも
区別します。

## 状態の表示

読み込み中、該当項目なし、成功、警告、失敗には、それぞれ同じ余白と文字の規則を使用します。
利用者が対応する必要のある失敗と競合は、画面内に残して原因と次の操作を示します。

保存成功は画面右上へ通知し、一定時間後に消します。通知と同時に編集画面内の保存状態も更新するため、
通知を見逃しても現在の状態を確認できます。`Ctrl+S`または`Command+S`による保存も、保存ボタンと
同じ通知を使用します。

## 狭い画面

幅が60rem以下の場合は、編集欄とプレビューを左右へ並べません。一覧の絞り込み入力、共有設定、
関連ノートは一列に並べます。固定表示する操作や通知は、360px幅でも本文を覆い続けない大きさに
します。

## キーボードと動き

リンク、ボタン、入力欄には、背景との違いを確認できるフォーカス枠を表示します。通知は
`aria-live`を使って読み上げます。OSで動きを減らす設定が有効な場合は、位置と色の切り替えに
伴うアニメーションを停止します。

## 検証

React単体試験では、操作、状態、支援技術向けの名前を確認します。Chromiumを使うブラウザー試験では、
production buildを360pxとデスクトップ相当の幅で開き、一覧、閲覧、編集、保存通知を確認します。
見た目を変更したPull Requestでは、代表画面の画像を試験結果として確認できるようにします。

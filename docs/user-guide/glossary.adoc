= 用語集

[#top]
この文書では、Marginalisの資料で使用する主な用語を説明します。一般的な意味と異なる用語や、
初めて読む人には役割を推測しにくい用語を対象とします。

各資料でも、専門用語を初めて使う箇所では、その文脈で必要な意味を短く説明してください。この
用語集は本文の説明を省略するためではなく、資料間で用語の意味をそろえるために使用します。

== AdocWeave

AsciiDoc文書を解析し、入力内容の検査、HTMLの生成、ノート間参照などに使う情報の抽出を行う
ライブラリです。Marginalisは、ノートを保存するときと表示するときにAdocWeaveを使用します。

初めて使う箇所では、バージョン番号だけでなく、その処理でAdocWeaveが担う役割を説明します。

== API

アプリケーション同士が機能やデータを利用するための接続方法です。MarginalisはREST APIとMCPを
提供します。

接続先や操作を説明するときは、「API」だけで済ませず、REST APIとMCPのどちらを指すか明記します。

== アクセス水準

利用者がノートへ実行できる操作の範囲です。``Read``は閲覧、``Edit``は閲覧と本文更新、``Manage``は
それらに加えて共有設定、削除、復元を許可します。後の水準は前の水準の操作を含みます。
所有者には``Manage``、ACL共有先には``Read``または``Edit``を適用します。

== archive

Marginalisのデータを書き出し、後から読み込むためのJSONファイルです。バックアップの作成や復元の
確認に使用します。ノート、ACL、削除状態、文献ライブラリ、文献情報の取込元と対応情報、数式マクロ
設定を含みますが、WebセッションやMCPトークンなどの認証状態は含みません。個別のノートをAsciiDoc
形式で書き出したファイルとは異なります。

設定名、コマンド、ファイル形式の名前では、コードと同じ``archive``の表記を使用します。一般的な
説明では「アーカイブ」または「JSON形式で書き出したデータ」と記述します。

== citation key

文献情報をAsciiDoc本文から引用するための、利用者が付ける短い識別子です。たとえば
``cite:[smith2024]``の``smith2024``がcitation keyです。同じ利用者の文献ライブラリ内では重複を
許しませんが、別の利用者は同じcitation keyを使用できます。

citation keyは編集できるため、文献情報を内部で識別するIDとは区別します。コードとAsciiDocの
記述例では``citation_key``または``citation key``と表記し、一般的な説明では必要に応じて
「引用に使う識別子」と補足します。

== 文献ライブラリ

利用者が論文や書籍の文献情報をまとめて管理し、複数のノートから引用するための保存領域です。
CSL-JSON形式の文献情報、citation key、更新番号を含みます。citation keyにはCSL-JSONの``id``を
使用します。ノートごとに文献情報を複製する保存方法とは異なります。

最初の実装では利用者ごとに分離し、本人だけが検索、追加、編集、削除できます。ほかの利用者との
共有は、所有者とアクセス水準を別途設計するまで提供しません。

== 論理スナップショット

保存方式に依存せず、ある時点の全ノート、ACL、文献ライブラリ、文献情報の取込元と対応情報、数式
マクロ設定をまとめたデータです。識別子の重複、存在しないデータを指す対応情報、所有者境界などを
検証した後に、バックアップの作成または復元へ使用します。コード上では``LogicalSnapshot``と表記します。

== AsciiDoc

見出し、箇条書き、表、リンク、ソースコード、数式などを文章中の記号で表現できる文書形式です。
Marginalisでは文書題名、``:marginalis-tags:``などの文書属性、本文を含む研究ノート全体の正本に
使用します。Marginalisが独自に決めた文書属性の名前は``marginalis-``で始まり、AsciiDocの組込み
属性と区別できます。

== base URL

Marginalisを外部から利用するときの基準となるURLです。REST API、MCP、ログイン後の戻り先などは、
このURLを基に組み立てます。サブパスを含む構成もあります。

設定名を示す場合は``baseUrl``や``MARGINALIS_BASE_URL``など、実際の名前を使用します。

== Dynamic Client Registration

MCPクライアントが、OAuthで必要になるクライアント情報をAuthorization Serverへ登録する仕組みです。
MarginalisのMCP接続では内蔵Authorization Serverが登録を受け付けます。資料で初めて使う箇所では
「動的クライアント登録」を併記します。

== Client ID Metadata Document

MCPクライアントがHTTPS URLを``client_id``として使い、そのURLでclient名や``redirect_uris``をJSON文書として
公開する仕組みです。略称はCIMDです。Authorization Serverは文書を必要時に取得するため、事前登録で
client情報を保存する必要がありません。

== CSRF

ログイン中のブラウザーを第三者のサイトから操作し、意図しない変更を送信させる攻撃です。
Marginalisは、変更操作に専用のトークンと正しい送信元を要求して防ぎます。

== Kanidm

利用者のログインとグループを管理する認証サービスです。MarginalisはKanidmから受け取った
利用者情報とグループ情報を検証し、利用できる機能を決定します。

== MCP

AIアプリケーションが外部のツールやデータを利用するための通信方式です。Marginalisでは、認可を
受けたMCPクライアントがノートの一覧取得、個別取得、作成、更新、削除を行えます。

== JSON Schema

JSONに含める項目、型、必須項目、値の制約を、プログラムが検査できるJSON形式で記述する仕様です。
Marginalisでは、MCP toolの入力と成功出力を``docs/mcp-tools.json``へ生成します。

== OAuth

利用者が、パスワードをMCPクライアントへ渡さずに、Marginalisの機能を利用する権限を与えるための
仕組みです。MarginalisではMCP接続の認可に使用します。

== OIDC

OpenID Connectの略称です。外部の認証サービスで確認した利用者情報を、Marginalisが安全に受け取る
ための仕組みです。MarginalisではKanidmによるログインに使用します。

OAuthはMCPクライアントへの認可、OIDCは利用者の認証に使用するため、両者を区別して説明します。

== OpenAPI

REST APIの接続先、入力、出力、エラーなどをJSONまたはYAMLで記述する仕様です。Marginalisでは
``docs/openapi.json``がREST APIの正式な仕様です。

== PKCE

OAuthの認可を開始したクライアントと、認可コードをトークンへ交換するクライアントが同じである
ことを確認する仕組みです。認可コードを第三者に取得された場合の不正利用を防ぎます。

== principal

ADR 0019で採用した、同じ利用者に属する一つ以上のOIDC identityをMarginalis内部でまとめる主体です。
OIDC identityは``issuer``と``subject``の組であり、認証サービスが発行します。principalは、認証サービスを
移した場合もノートの所有者や権限を同じ利用者へ結び付けるために使います。実装後もコード上の
``PrincipalId``は外部へ公開せず、REST APIとarchiveでは代表として選んだOIDC identityを使用します。

== REST API

HTTPを使ってノートの取得や更新などを行う接続方法です。MarginalisのREST APIは``/api/v3``以下で
提供します。詳しい接続先と入出力は link:../openapi.json[OpenAPI]を参照してください。

== revision

ノートが更新されるたびに変わる番号です。更新や削除を行うときに、読み込んだ時点のrevisionを
指定することで、ほかの操作による新しい変更を誤って上書きすることを防ぎます。
コード上の``Revision``型は1以上の値だけを受理し、HTTP、MCP、archive、SQLiteから受け取った値を
業務処理へ渡す前に同じ規則で検査します。

APIの項目名やコードでは``revision``と表記します。一般的な説明では、必要に応じて「更新番号」と
補足します。

== 作成経路

ノートを最初に保存した接続方法です。``web``、``rest``、``mcp``、``unknown``のいずれかを記録し、後から
変更しません。作成者の種類、AIの利用、内容の品質を証明する情報ではありません。

== 人手確認

利用者が、ノートの特定のrevisionを明示的に確認した事実です。確認したrevision、日時、確認者を
記録します。内容の正確性を保証するものではなく、revisionが変わった場合は現在の版を確認済みとは
扱いません。

== scope

OAuthでMCPクライアントへ許可する操作の種類です。Marginalisでは、ノートと文献情報について、
読み取り、書き込み、削除をそれぞれ区別します。scopeは操作の種類を制限しますが、ほかの利用者が
所有するノートへの権限を追加するものではありません。

== scope上限

利用者がMCPクライアントへ許可できるscopeの最大集合です。Marginalisでは、利用者がすべての
クライアントに適用する上限と、個別のクライアントに適用する上限を分けて保存します。実際に発行する
scopeは、この二つの上限、クライアントからの要求、利用者の同意のすべてに含まれるものだけです。

== SQLite

一つのファイルにデータを保存できるデータベースです。Marginalisでは、ノート、所有者、削除状態、
Webセッション、OIDCログイン試行、MCP client、認可済みクライアントの管理情報、認可code、tokenのhash
などを保存します。

== 正本

同じ情報が複数の場所にあり、内容が食い違ったときに、正しいものとして扱うデータまたは資料です。
たとえば、ノートの保存内容にはSQLite、REST APIの仕様には``docs/openapi.json``を優先します。

利用者向けの資料では「正本」だけで済ませず、「正式な仕様」「データの保存先」「優先して参照する
資料」など、その文脈での役割を具体的に説明します。

== ソフトデリート

削除したデータをすぐに消去せず、一定期間は復元できる状態で保管する仕組みです。Marginalisでは、
削除したノートを30日間保管し、期限を過ぎたデータを日次処理で物理削除します。

== トランザクション

複数のデータ変更を一つの処理として扱う仕組みです。すべての変更に成功した場合だけ保存し、途中で
失敗した場合は変更を残しません。

「原子的に処理する」とは書かず、どの変更をまとめ、失敗した場合に何が取り消されるかを説明します。

== 認可

認証された利用者やクライアントに、どの操作を許可するか判断することです。ノートを閲覧または
更新できるか、MCPクライアントが書き込みを行えるかなどを確認します。

== 認証

利用者やクライアントが誰であるか確認することです。Marginalisでは、利用者のログインにKanidmと
OIDCを使用します。

== ノート参照

AsciiDoc本文から別のノートへ移動するための参照です。
``xref:note:<ノートID>#<アンカーID>[表示ラベル]``の形式で記述します。アンカーIDと表示ラベルは
省略できます。

表示時には閲覧権限を確認します。参照先を閲覧できない場合は、存在しないノートと同じ未解決参照
として扱い、参照先のタイトルやノートIDをHTMLへ出力しません。閲覧できるノートのアンカーが
存在しない場合は、ノートの先頭へ移動します。

== Webhook

Marginalis内のデータ変更を、利用者が登録したURLへHTTP POSTで知らせる仕組みです。通知には
変更の種別と対象IDだけが含まれ、ノート本文は含まれません。登録、署名の検証方法、配送の
約束事は xref:webhooks.adoc#top[Webhook通知]で説明します。

= Web UIの画面設計

[#top]
この文書は、Marginalisのノート一覧、閲覧、編集、共有設定に共通する画面設計を説明します。
個別機能の操作は、 xref:web-ui-editor.adoc#top[AsciiDoc編集画面]など、それぞれの機能を説明する文書を
参照してください。

== 目的

画面では、ノートの本文と執筆領域を最も重要な情報として扱います。強い色や影を多用せず、
文字の大きさ、余白、整列によって情報のまとまりと操作の優先順位を示します。

アクセント色は、その場で最も進めたい操作にだけ使います。共通ヘッダーには新規ノートの1つを
置き、各画面の内容にはもう1つまでとします。同じ内容の中にアクセント色を2つ並べません。

画面から離れる操作や補助操作には、背景と境界線だけを使います。一覧の絞り込みや検索は
補助操作です。削除など取り消せない操作には、主要操作とは異なる警告色を使います。ノートの
削除には30日間の猶予がありますが、書誌情報の削除は取り消せません。

== 共通の画面構成

画面上部には、製品名と主要な画面への移動手段を置きます。機能数が少ない間は、内容のない
サイドバーを設けません。

移動先はノート、書誌、関係の図、設定の4つで、これに新規ノートを加えます。いま開いている画面には
``aria-current="page"``を付け、見た目でも示します。移動先の高さは指で押せる大きさを確保します。

幅が足りる画面では4つを横に並べます。狭い画面では「メニュー」ボタンへまとめ、押したときだけ
一覧を開きます。新規ノートはメニューへ入れず、どの幅でも直接押せる位置に残します。作成は移動より
頻度が高い操作だからです。

メニューは``details``と``summary``で作り、開閉にJavaScriptを使いません。幅が足りる画面では
``summary``を隠し、``::details-content``で開閉の状態にかかわらず内容を見せます。開いたメニューは
本文へ重ね、ヘッダーの高さを変えません。

本文領域の最大幅は、画面の用途に応じて変えます。

* 一覧と共有設定: 入力欄と複数の項目を見渡せる幅
* ノート閲覧: 長文の可読性を保ちながら、表、コード、数式へ広い横幅を使える幅
* 編集: 執筆とプレビューのそれぞれが長文を扱える幅

閲覧画面の本文上部にはnote IDとコピー操作を表示します。コピー結果は文字で示し、
``aria-live``を使って読み上げます。本文領域はデスクトップ相当の画面で最大96remまで広げ、
狭い画面では画面幅に合わせて縮めます。

段落やリストの1行の長さは、本文領域とは別に制限しません。1行に入る文字数は言語によって変わり、
一つの上限では決められないためです。全角文字は半角文字のおよそ2倍の幅を占めるため、英文向けの
目安をそのまま当てると、日本語では1文が途中で折り返されます。読みやすい行の長さは、本文領域の
最大幅で調整します。

== 目盛りとCSSの置き場所

色、角丸、書体などのdesign token（画面全体で共有する目盛り）は、
``frontend/src/styles/globals.css``のCSS custom propertiesで定義します。役割名はshadcn/uiの
規約に合わせ、``--background``（画面の地）、``--card``（浮かせた面）、``--primary``（主要操作）、
``--destructive``（取り消せない操作）、``--muted``（補助的な面と文字）、``--border``（境界線）、
``--ring``（フォーカス表示）のように、値ではなく役割で選びます。状態表示のために``--success``と
``--warning``も定義します。

色はoklch表記で書きます。oklchは明度、彩度、色相で色を表す表記で、色相を固定したまま明度だけを
変えられるため、ライト表示からダーク表示を導きやすくなります。各値には元のhex値をコメントで
併記します。姉妹サービスRenkanとは役割名と画面構成を共通にし、配色の値だけを各サービス固有と
します（Renkanは緑の暖色系、Marginalisは青の寒色系）。

画面部品はshadcn/uiのcomponentとTailwind CSSのユーティリティclassで組み立てます。部品では
トークンを参照するclass（``bg-primary``、``text-muted-foreground``など）だけを使い、色値を直接
書きません。余白と文字の大きさもTailwindの目盛りから選び、任意の値を書き並べません。採用している
componentは次のとおりです。追加手順は
xref:../developer-guide/development.adoc#top[GitHubを使う開発手順]を参照してください。

[cols="1,2",options="header",]
|===
|component
|用途
|``button``
|主要操作、補助操作、取り消せない操作のボタン
|``input``
|一行の入力欄
|``label``
|入力欄の名前
|``badge``
|タグなどの短い属性表示
|``alert-dialog``
|削除や破棄など、進む前に確認する画面
|``alert``
|利用者の対応が要る失敗の表示
|``card``
|情報のまとまりを浮かせて示す面
|===

``frontend/src/components/ui/``の生成コードは直接編集しません。横断的な調整は、生成コードが
出力する``data-slot``属性を対象にしたCSSで行います。

ユーティリティで書けない、または外部の部品と機構に密着した規則だけを、
``frontend/src/styles/``の手書きCSSに残しています。それぞれの担当は次のとおりです。

[cols="1,2",options="header",]
|===
|ファイル
|置くもの
|``tokens.css``
|余白・文字などの目盛りと、手書きCSSが使う旧色名の別名（色の正本は``globals.css``）
|``base.css``
|要素の既定とリンク、フォーカス表示、動きを減らす設定（base層に置き、componentを優先させる）
|``layout.css``
|ヘッダーの``details``/``summary``による開閉メニューの機構
|``components.css``
|編集画面の診断・競合表示など、移行順の都合で残る画面部品
|``editor.css``
|編集画面の枠組みとCodeMirrorの``.cm-*``上書き
|``graph.css``
|関係の図のSVGへの``data-*``属性スタイル
|``content.css``
|描画したノート本文の表示。AdocWeaveが生成するclassもここへ集める
|===

新しい規則は原則としてTailwindのユーティリティで書き、やむを得ず手書きCSSへ足す場合は
対象の画面のファイルへ置きます。

閲覧本文の文字の大きさは、画面部品とは別の目盛り（``tokens.css``の``--text-reading-body``、
``--text-reading-h3``、``--text-reading-h2``、``--text-reading-h1``、``--text-reading-title``）を
使い、用途ではなく見出しの階層で選びます。隣り合う段の比は1.12から1.18に収め、題名から本文まで
段階的に変えます。上位だけが大きく離れると、本文が相対的に小さく見えて読みにくくなるためです。

AdocWeaveは文書題名を``h1.document-title``、``==``の章見出しを``h1``として描画します。両方を同じ
大きさにすると、章見出しが題名と同じ扱いになり本文との差が広がります。``h1.document-title``と
``h1:not(.document-title)``を分けて指定します。

定義リストでは、用語を画面部品の書体と太字で示し、説明は用語より内側から始めて縦線で範囲を示します。
用語は見出しではないため、見出しの階層と競合しないよう本文と同じ大きさにします。

``citation``、``bibliography-anchor``、``source-block``、``math-latex``などはAdocWeaveが生成する
HTMLのclassです。Marginalisが決める名前ではないため``content.css``へ集め、改名しません。

手書きCSS（``frontend/src/styles/``）では、目盛りから外れた値を``cargo make frontend-verify``の
stylelintが拒否します。直値を書いてよいのは目盛りを定義する``globals.css``と``tokens.css``だけで、
CodeMirrorなど外部の部品へ合わせるためにやむを得ず外す場合は、その行に理由を書きます。Tailwindが
生成するCSSは検査の対象にしません。

ライト表示とダーク表示は、OSとブラウザーの``prefers-color-scheme``設定に従います。どちらの
表示でも、本文、補助情報、フォーカス、成功、警告、失敗を色だけに依存せず、文字または境界線でも
区別します。

== 一覧と書誌ライブラリー

ノート一覧の更新日は、画面へ日時を表示するときと同じ利用者のローカル時刻で区切ります。
たとえば「この日以降に更新」で指定した日の午前0時より前に更新したノートは含めません。

書誌情報のCSL-JSONを変更したまま別の項目を選ぶか編集を取り消す場合は、変更を破棄する前に確認します。
未保存の変更がある画面から離れる場合はブラウザーの警告を表示します。書誌情報の削除は復元できないため、
citation keyと操作結果を確認する画面を経てから実行します。

== 関係の図

関係の図では、点がノートと文献、線が参照と引用を表します。線の種類は色だけでなく、実線と
破線でも区別します。どこともつながっていない点は輪郭だけで示します。

配置は取得のたびに一度だけ計算し、その後は動かしません。動き続ける図は目で追いにくく、動きを
減らす設定とも相容れないためです。拡大と移動で見たい範囲へ寄れるようにします。

点に触れると、その点の近くへ吹き出しを出します。ノートでは種類、更新日時、タグ、文献では
種類、citation key、題名を示します。マウスのホバーとキーボードのフォーカスの両方で出します。
文献の題名は点のそばへ常時表示せず、長い題名も吹き出しで全文を確認できるようにします。ノートの
題名は点のそばへ常時表示します。吹き出しは実際の寸法を測り、点の上側を優先しながら上下左右を
図の枠内へ収めます。内容が図の高さを超える場合は、吹き出し内をスクロールして全文を確認できます。
マウスを点から吹き出しへ移す間は表示を短時間保ちます。拡大や移動で点の位置が変わった場合も、
表示位置を測り直します。

吹き出しはマウスの位置に依存し、読み上げの順序にも乗りません。そのため同じ内容を点自身の
名前（``aria-label``）にも持たせ、支援技術だけでも同じことが分かるようにします。吹き出し自体は
``aria-hidden``とし、同じ内容を二重に読み上げません。

図は情報へ至る唯一の手段にしません。同じ内容をつながりの多い順に並べた一覧としても示し、
キーボードと支援技術だけでも辿れるようにします。点を選ぶと、ノートは閲覧画面、文献は書誌
ライブラリーのその項目を絞り込んだ状態へ移動します。

範囲の絞り込みは2通りあります。語での絞り込みは、題名、本文、タグのいずれかにその語を含む
ノートと、それらが引用している文献だけを残します。起点での絞り込みは、1件のノートから何本の
線を辿るかを指定し、その範囲だけを残します。起点は閲覧画面の「周辺の関係」から渡し、URLの
``origin``と``depth``で表します。語はURLの``query``で表します。画面で条件を変更した場合もURLを
更新し、同じURLを開けば同じ範囲と検索結果が出ます。起点を指定している間は、図の
上に今の起点と階層数を示す帯を出し、そこから全体表示へ戻せるようにします。

一覧の絞り込み条件（タグと更新日）は図へ引き継ぎません。図の範囲は関係のたどり方で決まり、
一覧の並べ方とは別の条件だからです。

== 状態の表示

読み込み中、該当項目なし、成功の知らせは共通部品``StatusMessage``で示します。どれも待つか
眺めるだけでよい状態のため、同じ控えめな見た目にし、何が起きているかは文言で区別します。
支援技術へは``role="status"``で穏やかに伝えます。

利用者の対応が要る失敗は共通部品``ProblemAlert``で示し、``role="alert"``で割り込んで伝えます。
原因と次の操作を画面内に残します。競合も同じ扱いです。

保存成功は画面右上へ通知し、一定時間後に消します。通知と同時に編集画面内の保存状態も更新するため、
通知を見逃しても現在の状態を確認できます。``Ctrl\+S``または``Command\+S``による保存も、保存ボタンと
同じ通知を使用します。

== 狭い画面

幅が60rem以下の場合は、一覧の絞り込み入力、共有設定、関連ノートを一列に並べます。固定表示する操作や通知は、360px幅でも本文を覆い続けない大きさに
します。ヘッダーの移動先は「メニュー」ボタンへまとめます。

360px幅では、メニューを開いた状態も含めて、画面全体が横方向へはみ出さないことを確かめます。

表は横スクロールする枠``table-scroll``で包み、その内側でスクロールします。表そのものへ
``min-width``と``max-width``を同時に指定しても、``min-width``が優先されるため器の幅で頭打ちにできず、
本文ごと横へはみ出します。``thead``と``tbody``を別々の表として扱うと列がずれるため、外側に枠を足します。
枠は描画後にWeb UIが足すため、``table-scroll``はAdocWeaveが生成するclassではありません。表、コードブロック、数式は、本文ごと
横へ広げるのではなく、その要素の内側でスクロールします。

== 数式マクロ設定

数式マクロ設定は、コマンド名、引数の数、置換内容を一行で編集します。``\argmax``と``\bm``は定義例を
追加するボタンから入力できます。設定の適用範囲が所有するノートであり、共有先にも所有者の設定が
使われることを画面内で説明します。64件、コマンド名32文字、置換内容512文字、引数9個、コマンド名と
置換内容の合計16 KiBを上限とし、現在の件数と大きさを表示します。同じコマンド名や範囲外の引数参照は
保存前に示します。置換内容では波括弧を対応させ、パーセント記号は``\%``と記述し、末尾を単独の
バックスラッシュにしません。``def``は定義処理に使うためコマンド名へ指定できません。文字数はUnicodeの
コードポイント単位、合計の大きさは全項目のコマンド名と置換内容を合わせたUTF-8 byte数で数えます。
別の画面で先に保存された場合は競合として区別し、現在の入力を残します。旧版で保存した設定に現在の
安全性検査を満たさない項目がある場合は、その項目だけを数式へ適用しません。

== OAuth同意画面

MCPクライアントのOAuth同意画面は、通常画面と同じ色、書体、余白、カード、ボタンを使用します。
OAuthの認可endpointがサーバー側でHTMLを生成しますが、通常画面と同じHTML枠と配布済みCSSを
使用し、専用のJavaScriptは読み込みません。

同意画面には、クライアント名、クライアント識別子、移動先のhost、要求されたscopeを表示します。
loopback redirect URIの場合は、この端末上で動作するアプリへ戻ることを警告として示します。
許可を主要操作、拒否を補助操作として区別し、長い識別子やscopeはカード内で折り返します。

== ノートの削除

ノート閲覧画面の削除操作は、実効アクセス水準が``manage``の所有者にだけ表示します。実行前の
確認画面にはノートの題名と30日間の復元猶予を表示し、最初のフォーカスを「取り消す」へ置きます。
削除中は確認画面自体へフォーカスを保って二重送信と背景の操作を防ぎます。revision競合、権限の変更、
通信障害では「取り消す」へフォーカスを戻し、確認画面とノート本文を残したまま、次の操作を日本語で
示します。成功後はノート一覧へ移動し、削除したことを通知します。

ノート一覧から削除済みノートの画面へ移動できます。この画面には、現在の利用者が所有する
削除済みノートだけを表示し、題名、削除日時、完全削除予定、revision、残り日数を示します。
復元前にも題名を確認し、削除時と同じ確認画面のフォーカス制御を適用します。復元期限はブラウザー時刻から
案内しますが、可否はサーバー時刻で決定します。期限を過ぎていた場合は``retention_expired``応答を
画面に残して案内します。
削除済みノートの画面へ移動する前のタグ、更新日、ページはURLで引き継ぎます。通常の一覧へ戻る
場合は同じ位置を再現し、復元後はタグと更新日を保った先頭ページへ戻って完了を通知します。

== キーボードと動き

リンク、ボタン、入力欄には、背景との違いを確認できるフォーカス枠を表示します。通知は
``aria-live``を使って読み上げます。OSで動きを減らす設定が有効な場合は、位置と色の切り替えに
伴うアニメーションを停止します。

== 配布物の配信

ビルドしたJavaScriptとCSSは、実行ファイルへ埋め込んで``/assets/``から配信します。埋め込む一覧は
``crates/marginalis-web/build.rs``が``frontend/dist/assets``を走査して作ります。ファイル名を経路へ
書き並べません。分割読み込みで増えるchunkの名前には内容のhashが付き、変更のたびに変わるためです。

CodeMirrorを含む編集画面、関係の図、削除済みノート、数式マクロ設定、MCPのアクセス設定、
Webhook設定は経路ごとに分割し、その画面へ移動したときに読み込みます。一覧や閲覧だけを使う場合に、
編集器など別画面の実装を読み込ませません。

MIME typeは拡張子から決めます。知らない拡張子が現れた場合はビルドを止めます。誤ったMIME typeで
配信すると、ブラウザーはmoduleとして読み込まず、画面が黙って空になります。

== 検証

React単体試験では、操作、状態、支援技術向けの名前を確認します。編集欄の中身は、
CodeMirrorの文字描画が環境ごとに大きく変わるため、画像比較では隠します。行番号、枠、操作、
分割の位置は比較に残るため、配置の崩れは検出できます。Chromiumを使うブラウザー試験では、
production buildを360pxとデスクトップ相当の幅で開き、一覧、閲覧、編集、保存通知を確認します。
見た目を変更したPull Requestでは、代表画面の画像を試験結果として確認できるようにします。

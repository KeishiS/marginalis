= AsciiDoc編集画面

[#top]
この文書は、Web UIで長いAsciiDoc文書を編集する利用者と、編集機能を保守する開発者を対象に、
表示方式、入力操作、既知の制約を説明します。保存と競合のREST契約は xref:rest-api.adoc#top[REST API]、
編集基盤の採用理由は xref:../developer-guide/adr/0003-codemirrorをasciidoc編集基盤に採用.adoc#top[CodeMirror採用判断]、
装飾表示の設計は xref:../developer-guide/adr/0016-編集画面の装飾はadocweaveのspan注釈から導く.adoc#top[span注釈の採用判断]、
版履歴の設計は xref:../developer-guide/adr/0020-ノートの版履歴は完全な状態を追記して保存する.adoc#top[版履歴の採用判断]、
添付画像の設計は xref:../developer-guide/adr/0021-添付画像はsqlite内の不変objectとして版から参照する.adoc#top[添付画像の採用判断]を
優先してください。共同編集は対象外です。

== 表示方式

編集画面は次の二つの表示を明示的に切り替えます。切替では入力欄を作り直さないため、入力位置、
選択範囲、編集履歴、入力欄のスクロール位置を維持します。

[cols="1,1",options="header",]
|===
|表示
|用途
|執筆
|利用可能な横幅を本文入力に使用
|プレビュー
|利用可能な横幅をサーバー生成プレビューに使用
|===

== 入力操作

入力欄は行番号、長い行の折り返し、検索、元に戻す操作、やり直す操作を提供します。通常の
CodeMirrorキーボード操作に加えて、次の操作を固定しています。

[cols="1,1",options="header",]
|===
|操作
|結果
|``Ctrl\+S``または``Command\+S``
|現在の文書を明示的に保存
|``Tab``
|タブの挿入または選択した複数行の字下げ
|``Shift\+Tab``
|現在行または選択した複数行の字下げを解除
|``Ctrl\+F``または``Command\+F``
|文書内検索
|``F8``
|次の診断箇所へ移動
|``Ctrl\+Shift\+M``または``Command\+Shift\+M``
|診断の一覧を入力欄内に表示
|===

日本語IMEで変換している間は、保存とプレビュー更新を開始しません。変換を確定すると、確定した
完全な文字列を基にプレビュー更新を再開します。

=== 執筆中の装飾表示

執筆表示の入力欄は、原文の文字列をそのまま保ったうえで、記法に応じた見た目を重ねます。
``**太字**``は太字で、``__強調__``は斜体で表示し、見出しの行は大きな文字になります。
カーソル(選択範囲)がその記法に触れている間は、``**``などの記法文字が現れ、離れると
折り畳まれます。装飾は表示だけを変えるため、保存される内容は装飾の有無にかかわらず
同じです。

装飾の根拠になる記法の位置は、プレビューと同じサーバー解析から届きます。このため、
入力した直後の記法はプレビュー更新と同じ間隔(入力が止まってから350ミリ秒+通信時間)で
装飾され、装飾済みの本文は編集に即時追従します。

表示設定の「装飾」を押すと装飾を無効にでき、素の原文表示へ戻ります。もう一度押すと
装飾へ戻ります。

``*太字*``のような制約付き記法は、日本語の地の文に隣接していてもそのまま認識されます。
記法文字を二つ重ねる非制約記法(``**太字**``)は、単語の内側を装飾する場合に使います。

=== 入力補完

次の3つの文脈で、既存の情報が入力候補として表示されます。文字を入力すると候補が絞り込まれ、
``Enter``で確定します。候補を明示的に出す場合は``Ctrl\+Space``を押します。候補は補完を最初に
使ったときに取得します。

* **タグ**: ``:marginalis-tags:``の行では、閲覧できるノートで使用中のタグが候補になります。
カンマ区切りの2件目以降も同じように補完でき、同じ行に入力済みのタグは候補に出ません。
新しいタグは従来どおり自由に入力できます。
* **ノート間参照**: ``xref:note:``に続けて入力すると、閲覧できるノートの題名が候補になります。
確定するとnote IDと空の表示文``[]``が挿入され、閲覧画面では参照先の題名が表示されます。
* **引用**: ``cite:[``の中では、自分の文献ライブラリのcitation keyが候補になります。
カンマ区切りで複数を指定する場合も、同じ括弧内に入力済みのkeyは候補に出ません。

=== テンプレートから開始

新規作成の画面では、「テンプレート」タグを付けたノートを雛形として選べます。表示切替の
並びにある「テンプレートから開始」で選ぶと、そのノートの本文が入力欄へ入ります。既に入力が
ある場合は、置き換える前に確認を挟みます。テンプレートは通常のノートであり、タグを付け
外しするだけで候補へ出し入れできます。候補が無い場合、この操作は表示されません。MCPクライアント
からは``list_note_templates``で同じ一覧を取得できます( xref:mcp.adoc#top[MCP]を参照)。

=== 添付画像

保存済みノートでは「添付画像」からPNG、JPEG、WebPを選ぶか、本文の入力欄へファイルをドロップできます。
uploadが成功すると、入力位置へ``image::attachment:<attachment_id>[]``が挿入されます。画像1件は8 MiB、
一つのノートは32件かつ合計64 MiBまでです。SVG、HTML、音声、動画は受理しません。

追加しただけで本文や過去版から参照されていない画像は削除できます。一度でも保存した版から参照された
画像は、その版を再現するため個別には削除できません。ノートを削除しても30日間の復元期間中は保持し、
期限後にノートを完全削除すると全版と画像を一括して削除します。

=== 数学文書の定義、定理、証明

定義、命題、補題、定理、系、証明は、open blockへ数学文書用の``role``と題名を付けて記述できます。
プレビューと閲覧画面ではブロック全体を枠で囲み、題名、線、余白で本文との境界を示します。証明は
破線の枠になり、末尾へ証明終了記号が表示されます。この記号は表示だけに加えるため、AsciiDoc原文には
入りません。

[cols="1,1",options="header",]
|===
|種類
|role
|定義
|``definition``
|命題
|``proposition``
|補題
|``lemma``
|定理
|``theorem``
|系
|``corollary``
|証明
|``proof``
|===

次の例では、定義と定理、系が一つの``statement-number``を共有します。カウンタは最初の
``{counter:statement-number}``から1で始まるため、``:statement-number: 0``という文書属性は書きません。
別の値から始める場合は、最初の箇所を``{counter:statement-number:5}``のように記述します。

[source,adoc]
----
= 代数学のノート
:stem: latexmath

[#def-group.definition]
.定義 {counter:statement-number}（群）
--
集合 stem:[G] と演算 stem:[\cdot] が群の公理を満たすとき、組 stem:[(G,\cdot)] を群と呼びます。
--

[#thm-identity-unique.theorem]
.定理 {counter:statement-number}（単位元の一意性）
--
群の単位元は一意です。
--

[.proof]
.証明
--
二つの単位元 stem:[e]、 stem:[e'] に対して stem:[e=e\cdot e'=e'] です。
--

[#cor-example.corollary]
.系 {counter:statement-number}
--
<<thm-identity-unique>> から従います。
--
----

数学文書用の表示はopen blockへ適用します。一つのblockには上のroleを一種類だけ指定し、種類が文章でも
分かる題名を付けてください。任意のroleを画面のCSS classとして使うことはできません。

== 解析とプレビュー

CodeMirrorはAsciiDoc文書を文字列として編集します。AsciiDocの正しさをブラウザー内で独自に
判定せず、MarginalisがAdocWeaveを使って解析し、プレビューHTMLと診断を返します。この分担により、
未知の文書属性や将来追加する記法も入力時に失われません。

新規作成のプレビューは操作中の利用者の文献ライブラリを使います。既存ノートの更新では編集権限を
確認し、保存後の表示と同じくノート所有者の文献ライブラリを使って引用を解決します。

プレビューは入力が止まってから350ミリ秒後に更新します。更新に失敗した場合も、最後に成功した
プレビューを残します。位置が分かる診断は、入力欄の該当箇所へ波線を引いて示します。波線へ
ポインターを合わせると、理由と修正方法を表示します。キーボードでは``F8``で次の診断へ移動し、
``Ctrl\+Shift\+M``または``Command\+Shift\+M``で一覧を確認できます。入力を変更した時点で古い診断を
取り除き、変更後のプレビュー結果を受け取るまで再表示しません。位置を特定できない文書全体の診断と、
プレビューや保存に失敗したエラーは入力欄の外に表示します。

1行の文字数が上限を超えた場合は、上限と実際の文字数を示し、内容の区切りで改行するよう案内します。

執筆表示中もプレビューHTMLの生成を続けますが、MathJaxによる数式の組版はプレビューを表示する
時点で行います。このため、非表示中に生成が完了した数式も、プレビューまたは分割へ切り替えた後に
組版されます。組版済みの表示領域は、プレビューと分割を続けて切り替えても作り直さず、数式を
組版した状態に保ちます。

プレビューと閲覧画面では、すべてのコードブロックへ1から始まる行番号を表示します。
``[source,言語名,linenums,start=開始行]``で開始行を指定した場合は、その番号から表示します。

== 版履歴

閲覧画面の「版履歴」から、保存された版を新しい順に確認できます。一覧には版、変更時刻、変更者、
本文更新や共有設定変更などの変更種別を表示します。版を選ぶと、その時点のAsciiDoc原文を表示します。
比較元と比較先を選んで「差分を表示」を押すと、追加行と削除行を含む行単位の差分を確認できます。

編集権限以上がある場合は、過去版の原文を新しい版として復元できます。復元しても後の版は消えず、
所有者と共有設定も変わりません。削除済みノートの履歴は所有者だけが確認できます。本文の版を
復元する場合は、先に削除済みノートの一覧からノート自体を復元してください。

== 検証上限

ブラウザー試験では、UTF-8で512 KiB以下の5,000行の固定文書について、貼り付け、表示切替、
キーボード保存が完了することを確認します。320px幅と通常のデスクトップ幅では、表示切替の状態と
要素の配置をDOMから検査し、主要操作と入力欄が横方向へ失われないことを確かめます。
本番と同じCSPを適用し、CodeMirrorの基礎CSS、行番号gutterの配置、
分割幅の変更時にCSP違反が発生しないことも検査します。

production用``editor.js``は600,000バイトを上限とします。この上限はCodeMirror導入時の
545,570バイトに余裕を加えた値です。上限を超える場合は、機能追加だけを理由に広げず、配信経路の
分割または依存の削減を先に検討します。

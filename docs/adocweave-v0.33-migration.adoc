= AdocWeave 0.33移行判断

== 目的

[#top]
この文書は、AdocWeave 0.27.0から0.33.0への更新がMarginalisへ与える影響を記録します。
現行の入力方法はxref:rest-api.adoc#top[REST API]、archiveの変換手順は
xref:nixos.adoc#top[NixOSでの運用]を参照してください。

前回の更新はxref:adocweave-v0.27-migration.adoc#top[AdocWeave 0.27移行判断]にあります。

== 固定する依存

MarginalisはAdocWeave package版``0.33.0``を、release tagが指すcommitで使用します。CargoとNixの
両方で、このcommitと取得内容のhashを固定します。タグ作成前のcommitは最終的な依存には使用しません。

== 参考文献を構造化した入力として渡す

0.33.0は、利用側アプリが生成した参考文献を``RenderInputs``へ構造化して渡すAPIをRustとWASMの
両方で公開します。項目のcitation key、表示用のlabel、表示文字列を個別の値として渡すため、
AdocWeaveは表示文字列をAsciiDocとして再解釈しません。

Marginalisは、書誌ライブラリーから解決した参考文献をこのAPIで渡します。これにより、題名に
``C\+\+``、``++*++``、``pass:++[++...++]++``、HTMLに見える文字列などが含まれても、記法ではなく通常の文字として
表示できます。従来の実装にあった、AdocWeaveの記法開始条件をMarginalis側へ書き写す処理は
削除しました。記法の判定規則と文字列の安全な出力をAdocWeaveへ集約しています。

ノート本文で利用者が定義した同じcitation keyの参考文献は、従来どおり本文側を優先します。
生成した項目は引用から相互linkでき、番号を使う引用形式のlabelも維持します。

== 入力時の等幅記法を警告する

0.32.0で、単一のbacktickを等幅記法として使った箇所を報告する``monospace-boundary``規則が
追加されました。Marginalisはこの規則を警告として明示的に有効にします。入力を拒否する条件は
増えませんが、新しく保存または更新したノートでは、意図が等幅表記なら二つのbacktickを使うよう
案内します。この診断契約の変更に伴い、authoring profile版を15へ上げます。

== そのほかの版の影響

0.29.0と0.30.0のtextlint連携、0.31.0のLanguage Serverとhost実行の変更は、AdocWeaveをRustの
ライブラリとして組み込むMarginalisの実行経路へ影響しません。0.33.0で追加した不足resourceからの
前処理再開も、Marginalisが外部resourceを受理しないため入力契約を変えません。

== 保存形式への影響

SQLite schema versionは20のままです。v0.32.0のdatabaseはそのままv0.33.0で起動できます。
今回新しく拒否する本文はないため、database内の全ノートを事前に変換する必要はありません。

archiveには、復元時に使う解析契約を明示するため、AdocWeave package版``0.33.0``を記録します。
この契約変更に伴い、現行形式を``marginalis-archive-17``へ上げます。入力を拒否する条件は変わらないため、
archiveのnote profile版は5のままです。

v0.32.0が書き出したarchive 16は、v0.33.0の``migrate-archive``でarchive 17へ変換してから
取り込みます。変換では本文を0.33.0で再検証し、ノートの作成経路、人手確認状態、書誌情報の取込元と
対応情報を含む既存の記録を維持します。archive 16を現行archiveとして直接取り込むことはできません。

= 受入基準

[#top]
この文書は、各バージョンで繰り返す恒久的な受入基準を定めます。受入は自動検証を中心とし、
人手確認は自動化できない項目に限定します。実施日、結果、失敗または未実施がある場合の判断は
リリース用Pull Requestへ記載し、リポジトリ内に版別の記録は残しません。要件ごとの自動検証は
xref:traceability.adoc#top[要件と検証の対応表]を参照してください。

== 自動検証

Pull Requestと公開前の``release-gate``で次を確認します。

* React・TypeScriptの整形、静的解析、型検査、単体試験、依存監査、配布ビルド
* Rustの整形、静的解析、単体・結合試験、依存監査
* 共有Authorization Server crateの固定版、取得元、完全SHA、Nixの取得ハッシュの一致と、
本番バイナリーへの``testkit``非混入
* OpenAPIとTypeScript生成物の差分、RESTルーター、MCPツール定義の契約
* 所有者、閲覧者、編集者、対象外利用者の表示・操作・情報非漏洩
* ノート、ACL、参照、削除状態、revisionのtransaction整合性
* AdocWeaveの属性環境、コードブロック・数式HTML、対応する旧archiveから現行archiveへの全件再検証
* Kanidm、内蔵OAuth、TLS、サブパス、OIDC、MCP、バックアップ、削除、障害診断
* NixOS配備、空のデータベースの初期化、旧schemaの拒否

== 人手受入

自動検証が成功した後、リリース対象のcommitを配備した環境で次を確認します。実際の画面と
外部クライアントを通した振る舞いという、自動検証で代替しにくい確認に限定します。

[arabic]
. ログイン後にノートを作成し、一覧、閲覧、編集、プレビュー、保存を確認します。
. 所有者が閲覧者と編集者をACLへ追加し、それぞれの表示と操作範囲、および対象外利用者に
ノートが表示されず直接指定した操作が``404``になることを確認します。
. MCPクライアントからMCPへ接続し、RESTと同じ閲覧・更新結果になること、接続解除で
再認可なしにはアクセスできなくなることを確認します。
. 最新のアーカイブを本番から隔離した空のデータベースへ復元し、ノートと関連情報が一致する
ことを確認します。
. Webhookを登録して署名付きchallengeで有効化し、ノートの変更通知が受信サーバーへ届くこと、
署名を検証できること、secretが登録・再生成の応答以外に現れないことを確認します。

上記以外のUI詳細、文献機能、数式、削除・復元などの動作は自動検証でカバーし、対応する試験が
ない振る舞いを見つけた場合は試験を追加します。秘密情報、トークン、Cookie、実際のノート本文は
Pull Requestへ記載しません。

過去の版別受入結果は、各リリースタグ上の``docs/acceptance-results/``(v0.36.0以前)を参照して
ください。

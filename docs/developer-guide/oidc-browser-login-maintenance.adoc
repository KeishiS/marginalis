= 共有OIDCログインcrateの保守

[#top]
この文書は、Marginalisが取り込む共有OIDCログインcrateの版を更新する開発者に向けて、Marginalis側の
手順だけを説明します。crate自身の設計、検証の不変条件、上流での更新手順は、専用リポジトリ
https://github.com/KeishiS/oidc-browser-login[KeishiS/oidc-browser-login]の``README.adoc``と
``SECURITY.adoc``を正本とします。ここでは同じ内容を繰り返しません。

利用者から見たログイン設定は xref:../user-guide/nixos.adoc#top[NixOSで動かす]、標準OIDCへ依存し
共有crateへ分離した理由は
xref:adr/0015-利用者認証は標準oidcに依存しkanidmを参照実装とする.adoc#top[ADR 0015]を参照してください。

== 取り込み方

``oidc-browser-login``(中核)と``oidc-browser-login-testkit``(試験用)は、Marginalisのworkspaceには
含めません。ルート``Cargo.toml``の``[workspace.dependencies]``で、版と40桁の完全なcommit SHAを一度だけ
宣言します。branch名やtag名は依存指定に使いません。

中核は``marginalis-auth-oidc``(OIDC検証とsession use-caseへの接続)、``marginalis-sqlite``
(feature ``session``の保存port実装)、``marginalis-web``(feature ``cookie``の名前・属性)が
production依存として使います。testkitは契約試験のためのdev-dependencyに限定し、疑似IdPと
試験用鍵を製品バイナリーへ含めません。

Nixでは``flake.nix``の``cargoLock.outputHashes``へ、2 crate分の取得ハッシュを追加します。revisionの
正本は``Cargo.lock``であり、flake inputは追加しません。

== 責務の分担

上流リポジトリは、ID tokenの検証順序、claim読み取りのfail closed条件、署名アルゴリズムの制限、
疑似IdPによる全経路試験をCIで検証します。Marginalisが検証するのは、固定した版・URL・SHA・Nixの
ハッシュ(``cargo make shared-oidc-login``)、SQLite adapterが共有``LoginAttemptStore``契約を満たすこと
(``marginalis-sqlite::tests::sessions``)、既定設定でのKanidm実機ログイン(NixOS VM試験)です。

Cookieの発行、CSRF、Origin検査、session管理、許可claim値との照合による利用可否の判断は、従来どおり
Marginalis側の責務です。

== 固定revisionの更新手順

[arabic]
. 上流リポジトリで取り込み先commitの40桁の完全なSHAを確認します。
. ルート``Cargo.toml``の2 crateの``version``と``rev``を、同じ値へ同時に更新します。
. ``cargo check --workspace``を実行して``Cargo.lock``を更新します。
. ``flake.nix``の``cargoLock.outputHashes``のkeyとハッシュを更新します。keyは``<crate名>-<版>``です。
正しいハッシュは``nix build .#default``の失敗メッセージが示します。
. ``cargo make shared-oidc-login``を実行し、版、URL、revision、到達性、ライセンス、testkitの混入、
Nixのハッシュを確認します。
. ``cargo make verify``と``cargo make pre-push``を実行します。
. 上流の公開APIまたは検証動作が変わった場合は、Marginalis側のadapterと関連文書を同じ
Pull Requestで更新します。

== セキュリティー修正の反映

上流の脆弱性は上流の非公開advisoryで管理し、修正版を先に公開します。Marginalisは、公開された修正commitの
SHAへ固定revisionを更新し、上記の手順で統合を検証します。利用側の更新が終わるまで、脆弱な入力例、token、
client secret、内部URLなどを公開のIssue、Pull Request、ログ、試験成果物へ出しません。報告と公開の時期は
xref:security.adoc#問題の報告[セキュリティー方針]に従います。

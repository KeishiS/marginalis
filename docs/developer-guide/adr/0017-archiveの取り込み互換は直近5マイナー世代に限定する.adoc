= archiveの取り込み互換は直近5マイナー世代に限定する

[#top]
* 状態: 置換済み（ADR 0018）
* 日付: 2026-08-20
* 関連Issue: \#531
* 置換先: xref:0018-archiveは直前の公開済み保存契約からだけ移行する.adoc#top[ADR 0018]

== 背景

Marginalisのデータ更新は「更新前の環境で``export-archive``し、現行の``migrate-archive``で変換して
空のdatabaseへ``import-archive``する」流れを基本にしています。変換が受理する旧archiveは、
形式名・AdocWeave package版・note profile版の組(契約)を列挙した表で管理してきました。

この表はv0.8.0が書き出した``marginalis-archive-7``まで16契約に達し、次の費用が増えていました。

* 旧契約だけが必要とする処理(profile版4以前のタグ属性名の書き換え、来歴や文献取込の
基準値を持たない契約の分岐)がコードへ残り続ける
* 利用者向け文書に、もう使われない版別の移行手順と長い契約表が蓄積する
* 旧実行環境を再現して移行を検証するCI(schema 9のVM検査)を保守し続ける

一方で、実際の運用は「定期的にexportし、新しい版へimportし直す」であり、何世代も前の書庫を
直接持ち込む場面はまれです。

== 決定

*``migrate-archive``が受理する契約を、直近5マイナー世代のリリースが書き出したものに限定する*:
現行の版を含めて数え、たとえば現行がv0.46.0なら、v0.42.0以降(欠番を含む)が書き出した契約だけを
受理します。リリースで版を上げるたびに、5世代より前へ落ちた契約を
``SUPPORTED_MIGRATION_CONTRACTS``と利用者向け文書から削除します。契約の粒度は
「形式名 × AdocWeave package版 × note profile版」のままとし、同じ契約を複数の世代が共有する場合は
契約単位で残します。

*旧契約だけが必要とする処理は契約と一緒に削除する*: 削除した契約のための書き換え・補完・
検証分岐をコードへ残しません。旧実行環境を使う移行検証CIも削除します。

*5世代より前の書庫の救済経路は「過去のリリースでの持ち上げ」とする*: GitHub Releasesから、
その書庫へ対応していた過去のリリースを取得して一時的な環境で``migrate-archive``を実行し、
サポート範囲に入る契約へ書き出し直してから現行へ持ち込みます。この経路を利用者向け文書へ
明記します。

== 帰結

* 契約表・移行コード・文書が常に小さく保たれ、変換の検証対象が現実の運用範囲に一致します。
* 5世代より前の書庫の取り込みは1手順ではなくなります。過去のリリースはGitHub Releasesに
残るため到達手段は失われませんが、旧環境を用意する費用は利用者側へ移ります。
* 定期的にexportとimportを行う通常の運用では、影響はありません。
* 世代の数え方はマイナー版を単位とし、patch版は同じ世代に含めます。欠番(v0.43.0)も世代として
数えます。

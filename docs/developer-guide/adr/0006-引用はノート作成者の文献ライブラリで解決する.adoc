= 引用はノート作成者の文献ライブラリで解決する

[#top]
* 状態: 採用
* 日付: 2026-07-31

== 背景

ノートの本文には``cite:[smith2024]``と書けます。``smith2024``はcitation key、つまり文献情報を
指し示す短い識別子です。AdocWeaveはこのkeyを解決しません。どの文献かを決めるのは
Marginalisの役目です。

文献ライブラリは利用者ごとに分かれています（ xref:0004-文献ライブラリを利用者ごとに管理する.adoc#top[ADR 0004]）。
一方、ノートはACLによって他の利用者へ共有できます。したがって、共有されたノートを表示するとき、
どちらのライブラリでcitation keyを解決するのかを決める必要があります。作成者のライブラリと
閲覧者のライブラリで、同じkeyが別の文献を指すこともあります。

== 決定

*引用はノートを作成した利用者のライブラリで解決します。* 閲覧している利用者のライブラリは
参照しません。

``BibliographyRepository``には所有者のidentityを受け取る読み取り操作を置き、application層は
ノートの``owner``だけを渡します。下書きの表示では作成者がまだ確定していないため、操作している
利用者のidentityを使います。保存後は同じ利用者が作成者になるため、表示は変わりません。

*参考文献一覧は、描画のたびに引用済みの項目から組み立てます。* 保存する本文には含めません。
組み立てた``[bibliography]``ブロックを本文の末尾へ加えてからAdocWeaveへ渡すため、anchor、
本文からの相互link、項目から本文への戻りlinkは、手書きの参考文献と同じ仕組みで生成されます。
MarginalisはHTMLを組み立てません。

== 結果

同じノートは誰が見ても同じHTMLになります。REST、MCP、Web UIで表示が一致し、描画結果を利用者
ごとに分けて扱う必要がありません。

共有相手には、作成者が登録した文献情報が見えます。文献情報は文献の題名、著者、発行年であり、
ノート本文と同じ水準の内容です。ノートを共有した時点で本文は相手に見えているため、その本文が
引用している文献情報も見える扱いにします。共有相手のライブラリへ項目が複製されることはなく、
検索、追加、編集、削除の権限は本人のライブラリに限られたままです。

作成者がライブラリから項目を削除すると、その文献を引用していたノートの表示が変わります。
引用はcitation keyのまま表示され、参考文献一覧からその項目が消えます。保存済みの本文は変わり
ません。この状態は保存時の警告診断（``unknown_citation_key``）と同じ原因であり、書き手が気付ける
ようにするための表示です。

本文が同じcitation keyの``[[[key]]]``を既に定義している場合は、生成した項目を重ねません。同じ
anchorが二つある文書は成り立たず、著者が明示的に書いた記述を優先すべきだからです。

== 代替案

*閲覧している利用者のライブラリで解決する。* 読み手が自分の文献管理と同じ表記で読めます。
しかし同じノートが読み手ごとに違う文献を指すことになり、引用の意味が読み手によって変わります。
描画結果を利用者ごとに分ける必要も生じます。採用しません。

*両方のライブラリを順に引く。* 作成者に無いkeyを閲覧者のライブラリで補います。表示が
偶然一致することはありますが、どちらの文献が使われたのかを読み手も書き手も判断できません。
採用しません。

*参考文献一覧のHTMLをMarginalisで組み立てる。* 本文を変更せずに一覧を足せます。しかし
AdocWeave以外がHTMLを組み立てることになり、 xref:../architecture.adoc#top[アーキテクチャ]の方針から
外れます。引用と項目を結ぶanchorもAdocWeaveの検証を通らなくなります。採用しません。

*参考文献の項目を保存時に本文へ書き込む。* 描画のたびの組み立てが不要になります。しかし
ライブラリの項目を編集しても既存ノートの表示が古いままになり、文献情報の正本が二つに
分かれます。採用しません。

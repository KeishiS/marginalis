= リリース手順

[#top]
この文書は、Marginalisをリリースする手順を定めます。版ごとの変更内容、互換性への影響、
移行手順は https://github.com/KeishiS/marginalis/releases[GitHub Releases]のRelease Notesを
正本とし、リポジトリ内には蓄積しません。受入の確認項目は xref:acceptance.adoc#top[受入基準]を
参照してください。

[arabic]
. Cargo workspaceの版を上げ、``cargo make verify``の成功を確認して版上げのPull Requestを
作成します。版とNix packageの整合は``verify``内の``release-metadata``が検査します。あわせて、
archiveの取り込み互換(xref:adr/0017-archiveの取り込み互換は直近5マイナー世代に限定する.adoc#top[ADR 0017])
に従い、5世代より前へ落ちた契約を``SUPPORTED_MIGRATION_CONTRACTS``と利用者向け文書から
削除します。
. 外部のGit依存が意図した公開版を指していることを確認します。``cargo make shared-authorization-server``と
``cargo make shared-oidc-login``が、それぞれの共有crateについて、版が同じであること、同じリポジトリの
40桁の完全SHAから取得していること、``Cargo.lock``の取得元が宣言と一致すること、``flake.nix``に取得
ハッシュがあることを検査します。共有Authorization Serverが指すSHAが上流の公開済みタグに対応することの
確認は xref:mcp-authorization-server-maintenance.adoc#top[MCP Authorization Serverの保守]のタグ解決手順に
従い、上流の未公開コミットや、タグが付いていないコミットを指したまま公開しません。共有OIDCログインは
上流がまだ版のタグを公開していないため、指しているSHAが上流``main``の履歴に含まれることを確認します
(xref:oidc-browser-login-maintenance.adoc#top[共有OIDCログインcrateの保守])。
. xref:acceptance.adoc#top[受入基準]の人手受入を実施し、実施日、結果、失敗または未実施の項目が
ある場合の判断をリリース用Pull Requestへ記載します。
. 必須チェックの成功を確認し、 xref:development.adoc#top[GitHubを使う開発手順]のマージ方式で
Pull Requestを``main``へマージします。
. ``main``の先端で``release-gate``ワークフローを手動実行します。``release_tag``には作成予定の
タグを入力し、検証の成功を確認します。
. 検証した``main``の先端へリリースタグを作成してプッシュし、タグのプッシュで再実行される
``release-gate``も成功することを確認します。タグ起点の検証はタグの内容そのものに対して
行われるため、実行中に別のPull Requestが``main``へマージされても失敗しません(タグが
``main``上のcommitであることは検証されます)。
. タグのプッシュで実行された``release-gate``が成功すると、``draft-release``ジョブが同じタグの
内容から下書きのGitHub Releaseを自動作成します。公開した版の機械可読な契約を取得できるように、
対象タグに記録された``docs/openapi.json``と``docs/mcp-tools.json``が同名のassetとして下書きへ
添付されます。作業treeのファイルは使わないため、タグの検証後に``main``が進んでも公開内容は
変わりません。下書きの作成を確認し、Release Notesへ変更内容、互換性への影響、必要な場合は
データの移行手順を記載します。
+
[source,sh]
----
release_tag=v<MAJOR>.<MINOR>.<PATCH>
gh release edit "$release_tag" --notes-file <Release Notesのファイル>
----
. 下書きの``isDraft``が``true``であり、``assets``に``openapi.json``と``mcp-tools.json``だけが
それぞれ一つずつ含まれることを確認します。不足や重複がある場合は公開せず、下書きを修正します。
+
[source,sh]
----
test "$(gh release view "$release_tag" --json isDraft,assets \
  --jq '(.isDraft == true) and (([.assets[].name] | sort) == ["mcp-tools.json", "openapi.json"])')" = true
----
. Release Notesとassetの確認後に、下書きを公開します。
+
[source,sh]
----
gh release edit "$release_tag" --draft=false
----

パッチ版は予定へ固定せず、各通常版の公開後に、互換性を変えない不具合や移行手順の修正が必要に
なった場合だけ公開します。リリースを中止する場合は、タグとGitHub Releaseを作成せず、必要な修正を
通常のPull Requestとして続けます。過去の版の変更内容と移行手順はGitHub Releasesを、v0.36.0以前の記録は各タグ上の
``CHANGELOG.adoc``と``docs/acceptance-results/``を参照してください。

日次バックアップ、30世代の保持、四半期の復元確認については
xref:../user-guide/nixos.adoc#top[NixOSでの運用]を参照してください。
